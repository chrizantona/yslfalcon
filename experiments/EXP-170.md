# EXP-170 · Обучение в форме рабочего окна

## Идея
- **Родитель:** EXP-169 (тег `exp-169`) — пакет против переобучения: +0,001063 CI [−0,003414; +0,005789], inconclusive.
- **Изменение (одно):** и обучающие группы, и отложенная валидация строятся **как окно инференса**. Якорь берёт своих k ближайших по замороженному энкодеру — ровно так, как на запросе строится топ-20, — и модуль учится поднимать в этом наборе положительных. Junk (та же машина с той же камеры) маскируется в обоих слагаемых лосса: проверяющий выбрасывает его из списка, поэтому его место не несёт награды, а учить модуль любить или не любить junk — значит добавлять шум.
- **Откуда взялось обоснование:** в EXP-169 сид с лучшей отложенной точностью (0,9134) дал худший результат на фолде 0 (0,898435). Прокси мерил не то: один положительный против семи негативов, намеченных внутри 1 929 снимков, против двадцати кандидатов из топа энкодера по всей галерее. Довод пришёл из расхождения прокси с целью, а не из дев-фолда.
- **Что ещё меняется вместе с этим:** отложенный фолд 3 теперь меряет **сам прирост mAP@10** от перестановки — каждый его снимок работает запросом против остального фолда, — и он же выбирает вес смешивания. То есть на фолде 0 больше не выбирается ничего: ни эпоха, ни вес.
- **Известное несовершенство:** в наших фолдах окно содержит в среднем 3,68 положительных, а на фолде 0 их около 1,5 — наш обучающий пул плотнее по машинам. Внешний пул с четырьмя снимками на машину ближе к боевой плотности.
