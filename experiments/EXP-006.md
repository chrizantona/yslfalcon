# EXP-006 · k-reciprocal re-ranking эмбеддингов EXP-003

## Идея
- **Родитель:** EXP-003 (тег `exp-003`)
- **Изменение (одно):** сходство запроса и галереи пересчитывается k-reciprocal re-ranking (Zhong et al., CVPR 2017) по сохранённым эмбеддингам EXP-003; модель не переобучается
- **Гипотеза:** общие взаимные соседи подтянут позитивы из хвоста выдачи, прежде всего снятые с другого ракурса, поэтому mAP вырастет заметнее, чем R1. У запросов без совпадения в галерее общих соседей почти нет, так что отказ может стать точнее. Риск: серии почти одинаковых кадров с одной камеры займут набор соседей и вытеснят из него кадры с других камер.
- **Пакет изменений:** нет. k1 = 20, k2 = 6, λ = 0,3 — значения из статьи, по фолду 0 не подбираются.

## Запуск
- **Тег:** `exp-006`. Запущен с одного коммита с EXP-005.
- **Конфиг:** `configs/exp006_rerank_exp003.yaml`
- **Команда:** `CONFIG=configs/exp006_rerank_exp003.yaml setsid nohup bash scripts/pod_rerank_job.sh > status/job.log 2>&1 < /dev/null &` из папки прогона, куда скопированы эмбеддинги `artifacts/EXP-003/seed{0,1,2}/`
- **Протокол:** `val_v1`, фолд 0. Re-ranking считается по всем запросам и галерее фолда сразу, для калибровки отказа — заново по галерее без 30% машин. Порог — по z-score пересчитанного сходства, правило то же: лучший F1 при TNR ≥ 0,5.
- **Сиды:** 0, 1, 2 — по одному re-ranking на каждый сид EXP-003
- **Окружение:** CPU пода, numpy
- **Проверка:** mAP по сохранённым float16-эмбеддингам без re-ranking должен совпасть с EXP-003 (`source_mAP_saved_emb` в `metrics.json`)
- **Скорость:** время на одно ТС не меняется; время re-ranking на весь фолд 0 (1926 снимков) записывается отдельно
