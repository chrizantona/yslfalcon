# EXP-006 · k-reciprocal re-ranking эмбеддингов EXP-003

## Идея
- **Родитель:** EXP-003 (тег `exp-003`)
- **Изменение (одно):** сходство запроса и галереи пересчитывается k-reciprocal re-ranking (Zhong et al., CVPR 2017) по сохранённым эмбеддингам EXP-003; модель не переобучается
- **Гипотеза:** общие взаимные соседи подтянут позитивы из хвоста выдачи, прежде всего снятые с другого ракурса, поэтому mAP вырастет заметнее, чем R1. У запросов без совпадения в галерее общих соседей почти нет, так что отказ может стать точнее. Риск: серии почти одинаковых кадров с одной камеры займут набор соседей и вытеснят из него кадры с других камер.
- **Пакет изменений:** нет. k1 = 20, k2 = 6, λ = 0,3 — значения из статьи, по фолду 0 не подбираются.

## Запуск
- **Тег:** `exp-006`. Запущен с одного коммита с EXP-005.
- **Конфиг:** `configs/exp006_rerank_exp003.yaml`
- **Команда:** `CONFIG=configs/exp006_rerank_exp003.yaml setsid nohup bash scripts/pod_rerank_job.sh > status/job.log 2>&1 < /dev/null &` из папки прогона, куда скопированы эмбеддинги `artifacts/EXP-003/seed{0,1,2}/`
- **Протокол:** `val_v1`, фолд 0. Re-ranking считается по всем запросам и галерее фолда сразу, для калибровки отказа — заново по галерее без 30% машин. Порог — по z-score пересчитанного сходства, правило то же: лучший F1 при TNR ≥ 0,5.
- **Сиды:** 0, 1, 2 — по одному re-ranking на каждый сид EXP-003
- **Окружение:** CPU пода, numpy
- **Проверка:** mAP по сохранённым float16-эмбеддингам без re-ranking должен совпасть с EXP-003 (`source_mAP_saved_emb` в `metrics.json`)
- **Скорость:** время на одно ТС не меняется; время re-ranking на весь фолд 0 (1926 снимков) записывается отдельно

## Результаты
Фолд 0 `val_v1`, среднее ± std по сидам 0, 1, 2. Сохранённые float16-эмбеддинги воспроизводят mAP EXP-003 с точностью до 10⁻⁶, так что сравнение парное.

| Метрика | EXP-003 | EXP-006 | Δ | 95% CI Δ (bootstrap по машинам) |
|---|---|---|---|---|
| mAP | 0,719 ± 0,003 | 0,762 ± 0,002 | +0,043 | [+0,032; +0,054] |
| R1 | 0,661 ± 0,007 | 0,706 ± 0,003 | +0,045 | — |
| R5 | 0,894 ± 0,001 | 0,899 ± 0,004 | +0,005 | — |
| mINP | 0,670 ± 0,003 | 0,736 ± 0,004 | +0,066 | — |
| F1 при пороге | 0,652 ± 0,005 | 0,601 ± 0,005 | −0,051 | — |
| TNR при пороге | 0,508 ± 0,009 | 0,508 ± 0,002 | 0,000 | — |
| precision / recall при пороге | 0,597 / 0,717 | 0,556 / 0,655 | −0,041 / −0,062 | — |
| порог (z-score) | 3,707 ± 0,032 | 8,584 ± 0,109 | | |
| время на одно ТС, батч 1, мс | 13,8 | 13,8 | 0 | — |
| время re-ranking на фолд, с | — | 0,72 ± 0,02 | | |
| веса (fp32), МБ | 344,8 | 344,8 | 0 | — |

- Re-ranking всего фолда (1137 запросов + 789 снимков) занимает 0,72 с на одном проходе CPU, в пересчёте около 0,6 мс на запрос. Публичный тест того же порядка — 1860 снимков. Память растёт как N²: при N = 1926 матрица весов — 15 МБ, для галереи порядка 10⁶ нужен приближённый поиск соседей.
- Гипотеза про R1 не подтвердилась: R1 вырос так же, как mAP. Сильнее всего вырос mINP (+0,066): поднимается последний, самый трудный позитив.
- Отказ стал хуже: при том же TNR упали и precision, и recall. Вероятная причина — z-score плохо подходит к новой шкале. У большинства снимков галереи общих соседей нет и d_J ≈ 1, поэтому распределение по запросу — узкий пик с редкими выбросами; std мала, z-score лучшего кандидата раздут (порог 8,6 против 3,7) и хуже сравним между запросами. Это не проверено.

## Вывод
- **Решение:** accepted по ранжированию; для отказа re-ranking не использовать
- **Почему:** прирост mAP +0,043, доверительный интервал целиком выше нуля, разброс по сидам 0,002; выросли все срезы. F1 отказа на z-score пересчитанного сходства ниже на 0,051 — больше разброса по сидам.
- **Что дальше:** ранжировать с re-ranking, а порог отказа считать по z-score косинуса EXP-003 (одно изменение относительно EXP-006: источник score для отказа). Обучающие эксперименты продолжать от EXP-003, re-ranking — постобработка поверх.
