1. AFEM должен работать с глобальным embedding от SigLIP2, а не с patch tokens и не со spatial feature map.
2. На вход AFEM приходит один вектор на изображение размерности [B, D].
3. Задача AFEM — сделать общий semantic embedding SigLIP2 более полезным именно для ReID.
4. AFEM должен усиливать признаки, которые помогают различать людей: одежду, цветовые сочетания, аксессуары, форму, характерные визуальные детали.
5. AFEM должен ослаблять слишком общую или нерелевантную информацию: фон, общую сцену, признаки типа «это человек», освещение и другие признаки, которые плохо помогают различать ID.
6. Внутри AFEM исходный embedding должен преобразовываться несколькими независимыми обучаемыми ветками.
7. Каждая ветка должна иметь возможность выучить свой вариант представления исходной семантики.
8. Таких веток можно начать с 32.
9. Для каждой ветки должны быть обучаемые веса, определяющие, насколько сильно эта ветка влияет на итоговое представление.
10. Взвешенные выходы всех веток суммируются.
11. Помимо этих веток должна оставаться основная ветка, которая напрямую преобразует исходный SigLIP2 embedding.
12. Итог AFEM получается как основная ветка плюс взвешенная сумма дополнительных веток.
13. AFEM не должен содержать classifier, triplet loss или другую ReID-логику. Он только преобразует feature в feature.
14. На выходе должен получаться один refined semantic embedding на изображение.
15. Размерность выхода AFEM лучше сразу сделать такой, какая удобна для дальнейшего fusion с CNN-веткой.
16. Желательно сохранить residual-логику, чтобы AFEM не мог полностью уничтожить полезное pretrained-представление SigLIP2.
17. В начале обучения влияние дополнительной части AFEM желательно сделать небольшим, а дальше позволить ему обучаться.
18. AFEM не должен пытаться искать foreground человека по координатам изображения. Это не spatial attention.
19. AFEM не должен делить embedding просто на 32 последовательных куска. 32 группы — это 32 обучаемых преобразования исходного embedding, а не механическое разбиение размерности.
20. На первом этапе веса групп лучше сделать глобальными обучаемыми параметрами. Не нужно сразу делать отдельные веса для каждого изображения.
21. После AFEM должен получаться feature, который можно использовать как semantic branch в ReID.
22. Дальше этот feature уже можно объединять с feature от OSNet-AIN.
23. Смысл разделения такой: SigLIP2 даёт богатую общую семантику, AFEM делает эту семантику более discriminative для ID, OSNet-AIN отдельно даёт локальные appearance-признаки.
24. Главная проверка AFEM: один и тот же SigLIP2 с AFEM должен работать лучше, чем без AFEM. Если разницы нет, модуль либо не нужен, либо не обучается как задумано.
25. Перед интеграцией нужно выяснить только одну вещь в текущем пайплайне: какой именно глобальный embedding сейчас выходит из SigLIP2 и какая у него размерность. Всё остальное AFEM должен быть способен работать независимо от внутренней реализации SigLIP2.


1. OSNet-AIN должна быть отдельной CNN-веткой, которая получает то же входное изображение, что и SigLIP2.
2. Её задача — давать не семантическое, а локальное appearance-представление человека.
3. От OSNet-AIN нужно получить признаки, чувствительные к мелким визуальным деталям: текстуре одежды, узорам, обуви, сумкам, локальным цветовым сочетаниям, контурам и другим fine-grained особенностям.
4. Эта ветка должна дополнять SigLIP2, а не пытаться повторять его функцию.
5. SigLIP2 должен отвечать за более глобальную и семантическую информацию, OSNet-AIN — за локальную и multi-scale appearance-информацию.
6. Использовать лучше OSNet-AIN x1.0 как основной вариант.
7. Желательно брать pretrained веса, а не обучать OSNet-AIN с нуля.
8. На вход OSNet-AIN должно поступать изображение человека после того же базового crop, что используется для SigLIP2.
9. При этом нормализация и preprocessing для OSNet-AIN и SigLIP2 могут быть разными. Не нужно насильно использовать одинаковую normalization, если backbone были предобучены с разными preprocessing.
10. Из OSNet-AIN нужно брать последний информативный feature map до классификатора.
11.Внутренний классификатор OSNet-AIN из исходной модели использовать не нужно.
12. Из spatial feature map нужно получить один глобальный appearance embedding на изображение.
13. Для pooling лучше начать с GeM. Если его пока нет в пайплайне, можно начать с обычного global average pooling и потом отдельно проверить GeM.
14. После pooling получается вектор вида [B, C].
15. Этот вектор нужно отдельно спроецировать в фиксированную размерность, удобную для fusion. Например 512.
16. После projection должен получиться f_app — appearance embedding OSNet-AIN.
17. Перед fusion f_app желательно отдельно нормализовать.
18. OSNet-AIN должна иметь собственный auxiliary ReID loss, чтобы ветка сама училась различать ID и не становилась бесполезным придатком fusion.
19. Для auxiliary supervision можно использовать тот же тип losses, что и в основной ReID-ветке: classification loss и metric loss.
20. У OSNet-AIN должен быть свой BNNeck и свой classifier для auxiliary training.
21. Эти auxiliary classifier и BNNeck не обязаны участвовать в inference. Они нужны в первую очередь для обучения ветки.
22. В fusion нужно передавать именно feature до auxiliary classifier.
23. OSNet-AIN не должна напрямую получать output AFEM. Эти две ветки должны быть независимыми до момента fusion.
24. Правильная логика такая: изображение независимо проходит через SigLIP2 и OSNet-AIN.
25. SigLIP2 после AFEM даёт semantic feature.
26. OSNet-AIN после pooling и projection даёт appearance feature.
27. Только после этого два feature объединяются.
28. Первый вариант fusion лучше сделать простым concat, без cross-attention и без сложного взаимодействия feature maps.
29. Перед concat желательно привести обе ветки к одинаковой или близкой размерности, например 512 и 512.
30. Не стоит сразу складывать embeddings через обычное сложение. SigLIP2 и OSNet-AIN живут в разных feature spaces.
31. Не нужно сейчас делать fusion между patch tokens SigLIP2 и feature map OSNet-AIN. Это можно рассматривать только после того, как late fusion покажет пользу.
32. AIN внутри OSNet нужна для большей устойчивости appearance-признаков к изменениям стиля изображения.
33. Под стилем здесь имеются в виду освещение, цветовой баланс, контраст, особенности разных камер и доменов.
34. Это особенно полезно, если ReID работает между разными камерами или датасетами.
35. При этом AIN не должна полностью убрать цветовую информацию, потому что цвет одежды важен для ReID. Нужно использовать стандартную архитектуру OSNet-AIN, а не добавлять агрессивную InstanceNorm поверх всего feature.
36. На первом этапе OSNet-AIN можно fine-tune целиком, если обучение стабильное.
37. Если модель начинает переобучаться или сильно портятся pretrained features, можно заморозить ранние слои и обучать только последние stages и projection head.
38. Learning rate для pretrained OSNet-AIN лучше сделать ниже, чем для новых fusion/projection слоёв.
39. На выходе OSNet-AIN должен быть один компактный appearance descriptor на изображение.
40. Этот descriptor должен самостоятельно быть полезен для ReID, даже без SigLIP2.
41. Но основной смысл OSNet-AIN появляется тогда, когда её ошибки отличаются от ошибок SigLIP2.
42. Если SigLIP2 путает двух людей с похожей общей одеждой, OSNet-AIN должна помогать различать их по мелким деталям.
43. Если OSNet-AIN ошибается из-за blur, плохого разрешения или слабой текстуры, SigLIP2 может компенсировать это более глобальными признаками.
44. Нужно отдельно проверить качество OSNet-AIN без fusion.
45. Нужно отдельно проверить SigLIP2 без OSNet-AIN.
46. Нужно проверить SigLIP2 + OSNet-AIN.
47. Если fusion не лучше обеих отдельных веток, значит либо признаки слишком похожи, либо fusion реализован неудачно, либо одна ветка доминирует над другой.
48. Полезно следить за нормами embeddings обеих веток. Одна ветка не должна иметь намного больший scale и подавлять вторую.
49. Не нужно делать OSNet-AIN чрезмерно большой. Её смысл здесь — быть специализированным и сравнительно лёгким дополнением к SigLIP2.
50. 
Итоговая роль OSNet-AIN в пайплайне должна быть простой: взять изображение человека, извлечь устойчивые multi-scale локальные appearance-признаки, превратить их в компактный ReID embedding и передать этот embedding в fusion с refined semantic feature от SigLIP2+AFEM.
