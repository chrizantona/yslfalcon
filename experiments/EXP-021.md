# EXP-021 · exp2, ViT-L/14

## Идея
- **Родитель:** EXP-020.
- **Изменение:** fp16 autocast полного цикла инференса ViT-L; отдельно публичные веса и финальный seed0 с BNNeck.
- **Гипотеза:** больший бэкбон и перенос домена улучшат межкамерный поиск; проверяем каждую ступень отдельно.
- **Пакет изменений:** нет.

## Запуск
- **Тег:** `exp-021`; `git diff exp-020 exp-021`.
- **Внешние веса и данные:** [DATA.md](../DATA.md), закреплённая ревизия LAION/OpenCLIP и sha256; для EXP-022 — публичная версия 1 VERI-Wild test.
- **Потоковость:** да, каждый запрос независимо, TTA и реранкер не добавлены.
- **Конфиг:** `configs/exp2.yaml`.
- **Команда:** `CONFIG=configs/exp2.yaml GPU=3 PREPARED_ENV=/workspace/yslfalcon_runs/exp1/.venv setsid nohup bash scripts/pod_benchmark_job.sh > status/job.log 2>&1 < /dev/null &`.
- **Протокол:** `configs/val_v2.yaml`, фолд 0; обучение на фолдах 1–3 по vehicle_id, фолд 4 нетронут. Для EXP-022 обучение только на внешних машинах.
- **Сиды:** не применяется.
- **Окружение:** H200, GPU 1/3/2; Python 3.13.7, Torch 2.10.0+cu130, torchvision 0.25.0; `requirements.txt`, `requirements-pod.txt`; `pytest==9.1.1`. Отдельная venv без системных пакетов.
- **Директория на поде:** `/workspace/yslfalcon_runs/exp2/`; названия по просьбе пользователя.

## Условный ночной запуск
`setsid nohup bash scripts/pod_night_job.sh > status/night.log 2>&1 < /dev/null &` из exp1. Сначала EXP-020 и EXP-021 параллельно. GPU 3 передаётся обучению только после независимого замера скорости. Для цепочки EXP-022 → EXP-023 → EXP-024 требуется прирост среднего mAP@10 EXP-020 над 0,710 больше max(0,004, std новых сидов). Условие и справочный результат EXP-016 (0,773) записаны в `configs/exp1.yaml`; решение сохраняется в `status/gate.json`.

## Результаты
После обучения `reid.precision_eval` пересчитывает тот же seed0 в fp16 через неизменённый `evaluate_fold`, сохраняет AP и эмбеддинги. Прирост/падение сравнивается с fp32 этого же чекпоинта.

Ожидаются. Сравнение родителя и EXP-016: mAP@10, R1, R5, отказ и порог, полный mAP/mINP справочно, полный цикл скорости, VRAM и размер весов. Опубликованные показатели отказа `val_v2` и `F1_strict` сохраняются раздельно; неоднозначность junk-кандидата описана в README. Замер H200 не заменяет проверку RTX A5000.
