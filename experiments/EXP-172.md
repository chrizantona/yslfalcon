# EXP-172 · численно устойчивый Giant VehicleID teacher

## Идея
- **Родитель:** EXP-167 (тег `exp-167`), завершившийся численным сбоем до первой эпохи.
- **Изменение (одно):** в первом transformer-блоке timm использовать явное scaled-QK → softmax → AV attention
  вместо fused SDPA; остальные 39 блоков, activation checkpointing, batch 128, данные, аугментации, loss и LR те же.
- **Гипотеза:** unfused BF16 backward устранит NaN первого блока, не меняя модель или обучающий сигнал.
- **Пакет изменений:** нет; это замена вычислительного ядра одной математически эквивалентной операции.

## Запуск
- **Статус:** завершён 20.09.2026; десятишаговый численный preflight и полный прогон конечны.
- **Тег:** `exp-172`; дифф с родителем: `git diff exp-167 exp-172`.
- **Внешние веса и данные:** те же закреплённые Giant и официальный VehicleID train из `DATA.md`.
- **Потоковость:** да; внешние данные используются только при обучении учителя.
- **Конфиг:** `configs/exp172_siglip2_giant_vehicleid_teacher_unfused0.yaml`.
- **Протокол:** `val_v2`, dev-фолд 0 после каждой эпохи; фолд 4 не используется.
- **Сиды:** 0; исследовательский учитель.
- **Окружение:** H200 GPU 3; GPU 0/1 не трогаются.

## Численная проверка
- EXP-167: шаг 0 конечный; на шаге 1 ID, SupCon и triplet по отдельности давали NaN в одних и тех же семи
  параметрах первого attention-блока при fused SDPA + checkpointing.
- Полное отключение checkpointing не подходит: первый forward batch 128 занял 138,45 ГБ и запросил ещё 864 МиБ.
- Unfused attention только в блоке 0: два шага и отдельные backward всех трёх loss конечны; пик 42,49 ГБ.
- Десять последовательных optimizer steps с полной проверкой всех градиентов и параметров: все конечны; peak VRAM
  `42,49 ГБ`, выделенная память после прогрева стабильна `38,83 ГБ`.
- Полный набор после слияния со свежим `main` и добавления конфигурационного предохранителя: `131 passed`; три прежних warning относятся к
  намеренно пустому срезу теста метрики.

## Результаты
Imprinting обработал 113 346 кадров официального VehicleID train, 13 164 класса, от 2 до 142 кадров на класс.
Обучение прошло все 10 эпох без NaN; один PK-батч содержал 32 машины × 4 кадра. Лучший state выбирался только по
`val_v2` fold 0 после каждой эпохи и оказался на эпохе 4. Фолд 4 не использовался.

| Метрика | Значение |
|---|---:|
| mAP@10 | **0,784694** |
| R1 / R5 | 0,751099 / 0,897098 |
| score отказа | 0,843186 |
| F1 / TNR / threshold | 0,811538 / 0,917031 / 4,290420 |
| полный mAP / mINP | 0,790881 / 0,764326 |
| F1 strict | 0,044304 |
| время обучения | 132,53 мин |

Динамика dev mAP@10 по эпохам: `0,774633`, `0,774478`, `0,781229`, **`0,784694`**, `0,781391`,
`0,778071`, `0,778492`, `0,780315`, `0,782387`, `0,781106`. После эпохи 4 метрика не вернулась к максимуму,
хотя ID-loss монотонно снизился с 20,043 до 11,677. Скорость обучения стабилизировалась около 72 изображений/с.

Относительно raw Giant EXP-166 fine-tuning на VehicleID дал `+0,175598` mAP@10. При этом учитель остаётся ниже
EXP-048 на `−0,047406`, ниже одиночной базы EXP-054 на `−0,109203` и не является кандидатом для прямого инференса.

Срезы mAP: знакомый ракурс на другой камере — 0,834600, неизвестный — 0,745939; камеры 89/90 — 0,752729;
маленькие рамки — 0,749086; обрезанные — 0,780682; такси/каршеринг — 0,748016.

H200 FP16 benchmark: полный цикл batch 1 — 16,94 мс, forward — 5,83 мс; лучший throughput — 238,1 FPS
при batch 32; peak VRAM 3 399 МБ, загрузка весов 54,98 с. Башня содержит 1 163,7 млн параметров, embedding 1536.
Checkpoint FP32 занимает 4 735,7 МБ, поэтому превышает лимит инференсных весов 2 ГБ и применим только как teacher.

## Вывод
- **Решение:** reference. Численная гипотеза EXP-172 подтверждена: unfused attention первого блока устранил сбой
  EXP-167 и позволил закончить тот же рецепт. VehicleID заметно улучшил raw Giant, но абсолютное качество ниже
  компактных LCT-моделей; полезность этого checkpoint как учителя должна проверяться отдельным экспериментом
  дистилляции, без автоматического продолжения после отрицательной прямой метрики.
