# EXP-016 · Суп весов трёх сидов EXP-010

## Идея
- **Родитель:** EXP-010 (тег `exp-010`)
- **Изменение (одно):** веса трёх чекпоинтов EXP-010 (сиды 0, 1, 2) усредняются поэлементно в одну модель (uniform model soup, Wortsman et al., 2022), включая статистики BN. Без переобучения.
- **Гипотеза:** все три сида дообучены с одного старта (EXP-009) и лежат в одном бассейне минимума, поэтому среднее весов работает как ансамбль, но стоит одного прогона модели. Ожидаем прирост до уровня EXP-015. Если суп развалится (mAP ниже одного сида) — сиды слишком разошлись.
- **Пакет изменений:** нет
- **Цена:** скорость и размер — как у EXP-010

## Запуск
- **Тег:** `exp-016`. EXP-011…EXP-016 запущены с одного коммита
- **Конфиг:** `configs/exp016_soup_exp010_seeds.yaml`
- **Команда:** `EVALS="configs/exp011_ref_fastreid_r50ibn_veriwild.yaml configs/exp012_ref_fastreid_r50ibn_vehicleid.yaml configs/exp013_ref_clipreid_vitb16_vehicleid.yaml configs/exp014_ref_clipreid_vitb16_veri.yaml" ENSEMBLES=configs/exp015_ensemble_exp010_seeds.yaml SOUPS=configs/exp016_soup_exp010_seeds.yaml GPU=<id> setsid nohup bash scripts/pod_eval_job.sh > status/job.log 2>&1 < /dev/null &`
- **Протокол:** `val_v1`, фолд 0; сравнение с EXP-010 bootstrap-ом по машинам
- **Сиды:** один суп из трёх сидов
- **Чекпоинт:** суп сохраняется в `/workspace/checkpoints/` под случайным именем; имя записывается после прогона

## Вывод
- **Решение:** accepted — новый бейзлайн
- **Почему:** прирост +0,004, интервал выше нуля; скорость и размер как у одной модели; почти весь выигрыш ансамбля EXP-015 без его цены. Отказ не изменился (F1 0,716 против 0,718 ± 0,014).
- **Что дальше:** re-ranking на эмбеддингах супа с порогом отказа по косинусу; суп как стандартный последний шаг для экспериментов с тремя сидами от одного старта.
