# EXP-019 · Потоковый k-reciprocal re-ranking поверх EXP-016

## Идея
- **Родитель:** EXP-016 (тег `exp-016`) — текущий бейзлайн
- **Изменение (одно):** сходство запроса с галереей пересчитывается потоковым k-reciprocal re-ranking по сохранённым эмбеддингам EXP-016 (`reid.rerank`, `StreamingRerank`). Модель та же, без переобучения.
- **Как устроено (потоковость):**
  - галерея обрабатывается один раз, как статичная база: расстояния, взаимные соседи, их расширение и векторы Жаккара;
  - каждый запрос — отдельно: снимок галереи считается его взаимным соседом, если он среди k1 ближайших к запросу, а запрос попал бы в k1 ближайших к этому снимку;
  - вектор запроса усредняется с k2 − 1 ближайшими снимками галереи; расстояние = 0,7·Жаккар + 0,3·нормированное расстояние;
  - другие запросы не используются, это проверяет тест `test_streaming_rerank_scores_each_query_without_the_others`.
- **Отличие от EXP-006 (invalid):** там соседи строились по всем запросам и галерее вместе. Здесь векторы галереи не содержат запросов, так что это приближение исходного алгоритма.
- **Гипотеза:** общие соседи в галерее подтянут позитивы с другого ракурса и поднимут mAP@10. Потоковый вариант слабее пакетного (EXP-006 давал +0,043 полного mAP на `val_v1`), ожидаем меньший, но положительный прирост. Порог отказа по z-score пересчитанного сходства может ухудшиться, как в EXP-006.
- **Пакет изменений:** нет. k1 = 20, k2 = 6, λ = 0,3 — из статьи, по фолду 0 не подбирались.
- **Внешние веса и данные:** нет (эмбеддинги EXP-016).
- **Потоковость:** да.

## Запуск
- **Тег:** `exp-019`
- **Конфиг:** `configs/exp019_streaming_rerank_exp016.yaml`
- **Команда:** `CONFIG=configs/exp019_streaming_rerank_exp016.yaml setsid nohup bash scripts/pod_rerank_job.sh > status/job.log 2>&1 < /dev/null &`; в папку прогона копируются `artifacts/EXP-016/val_fold0/{query,gallery}_emb.npy` и `metrics.json`
- **Протокол:** `val_v2`, фолд 0; сравнение с EXP-016 bootstrap-ом по машинам на mAP@10
- **Сиды:** один результат (EXP-016 — один суп)
- **Окружение:** CPU пода, numpy
- **Скорость:** время на одно ТС не меняется (re-ranking в замер организаторов не входит); отдельно записываются время подготовки галереи и среднее время на запрос — всё должно уложиться в лимит прогона около 4 минут
