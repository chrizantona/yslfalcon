# EXP-104 · Преобразования эмбеддингов по галерее (без обучения)

## Идея
- **Родитель:** EXP-090 (тег `exp-090`) — суп трёх сидов EXP-089, лучшая точка: mAP@10 0,8976, отказ 0,920. Модель не трогается, работаем на её сохранённых эмбеддингах фолда 0.
- **Изменение (одно):** к эмбеддингам применяется преобразование, посчитанное **только по галерее**:
  - `centre` — вычесть средний вектор галереи с обеих сторон и перенормировать;
  - `whiten` — PCA-отбеливание по галерее со степенью 0,25 и 0,5 (0 — ничего, 1 — полное);
  - `alpha_qe` — запрос заменяется взвешенным средним себя и k ближайших снимков галереи, вес cos^3, k = 1 и 2.
- **Гипотеза:** почти у каждого запроса в галерее лежит кадр той же машины с той же камеры, а у ~75% — практически та же рамка; метрика выбрасывает его как junk (в среднем 0,99 junk-кандидата в топ-10 у EXP-090). Это более чистый снимок той же машины, и его соседство может поправить ранги 2–5, где и теряется метрика: R5 уже 0,976, а R1 только 0,878. Центрирование и отбеливание бьют по другому: общее направление набора камер не несёт информации о машине, а в EDA вычитание среднего по камере давало +22–32% mAP (но подавать `camera_id` нельзя, поэтому берём среднее всей галереи).
- **Почему это разрешено:** протокол потоковый — вся галерея доступна заранее, запрещено только использовать другие запросы. Ни одно преобразование здесь не смотрит на другие запросы: среднее и ковариация считаются по галерее, расширение запроса идёт по снимкам галереи. Это отличает EXP-104 от недействительного EXP-006.
- **Риск:** потоковый k-reciprocal re-ranking уже проваливался (EXP-019, −0,068). Варианты заданы заранее, но выбор лучшего из шести на том же фолде завышает оценку — принимаем только при CI выше нуля и подтверждаем на фолде 4.
- **Пакет изменений:** нет; код — `src/reid/gallery_transforms.py`.

## Запуск
- **Тег:** `exp-104` · дифф с родителем: `git diff exp-090 exp-104`
- **Внешние веса и данные:** нет; вход — `artifacts/EXP-090/val_fold0` (fp32-эмбеддинги супа, Release `exp-090`).
- **Потоковость:** да — запрос обрабатывается независимо от других запросов.
- **Конфиг:** `configs/exp104_gallery_transforms.yaml`; шесть вариантов зафиксированы в нём до запуска.
- **Команда:** `PYTHONPATH=src python -m reid.gallery_transforms --data-config configs/data.yaml --val-config configs/val_v2.yaml --config configs/exp104_gallery_transforms.yaml`
- **Протокол:** `configs/val_v2.yaml`, фолд 0; фолд 4 не трогается. Порог отказа пересчитывается для каждого варианта так же, как в `reid.evaluate`.
- **Сиды:** не применимо, преобразования детерминированы.
- **Окружение:** второй под (rougenn), H200; venv EXP-030. Обучения нет, считается минуты.
- **Решение:** для каждого варианта — парный bootstrap по машинам против варианта `base` (он обязан повторить 0,8976). Принимаем только при CI выше нуля; отдельно смотрим, не портится ли отказ.
