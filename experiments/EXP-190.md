# EXP-190 · Поправка на ракурс поверх итоговой конфигурации

## Идея
- **Родитель:** EXP-178 (тег `exp-178`) — итоговая конфигурация: суп EXP-164 + реранкер (окно 20, вес 0,25), без αQE, одна галерея как на тесте, порог отказа 7,2429. Фолд 0: mAP@10 0,917156.
- **Изменение (одно):** после ранжирования из сходства вычитается δ, если ракурс кандидата совпадает с ракурсом запроса: `sim − δ · same(q, g)`. Модель и реранкер не меняются.
- **Откуда гипотеза (разбор ошибок, фолд 0):** 77% потерянного AP приходится на истинные кадры, снятые с другой стороны, чем запрос, при их доле 66%; неверный первый ответ совпадает с запросом по ракурсу в 80% случаев против 37% у случайного кадра галереи. Двойник в ракурсе запроса обходит нужную машину, снятую с другой стороны. Оценка на тех же данных (δ подбирался там же): до +0,009 mAP@10 — оптимистичная, поэтому здесь проверка честная.
- **Ракурс — из пикселей, камера не используется.** Три варианта:
  - `clip_hard` — метки CLIP zero-shot из `protocol/attributes.csv`; на тесте потребует CLIP на инференсе;
  - `head_hard` — softmax-голова на нашем эмбеддинге, обученная на фолдах 1–3 по меткам CLIP; на тесте почти бесплатна;
  - `head_soft` — та же голова, штраф пропорционален вероятности совпадения ракурсов `Σ p_q(v) p_g(v)`.
- **Правила:** δ выбирается по максимуму mAP@10 на фолде 0 из сетки 0…0,15; на фолде 4 — один просмотр при этом δ, ничего не подбирается. Порог отказа переносится как есть; отказ считается официально (верхний ответ верен, если это та же машина).
- **Риски:** ракурс CLIP шумный; штраф опускает и истинные кадры в том же ракурсе (их 34%); выигрыш фолда 0 может не перенестись.
- **Пакет изменений:** нет.

## Запуск
- **Тег:** `exp-190` · дифф с родителем: `git diff exp-178 exp-190`
- **Конфиг:** `configs/exp190_view_penalty.yaml`
- **Команда:** `PYTHONPATH=src python -m reid.view_penalty --data-config configs/data.yaml --val-config configs/val_v2.yaml --config configs/exp190_view_penalty.yaml` на GPU 1, из копии репо в `/workspace/yslfalcon_runs/EXP-190/`.
- **Протокол:** фолд 0 — подбор δ; фолд 4 — объявленный просмотр (как EXP-171), один раз; обучения нет, кроме головы ракурса на фолдах 1–3.
- **Окружение:** второй под (rougenn), H200, GPU 1; venv EXP-030.
- **Решение:** вариант берётся в финал, если на фолде 4 прирост mAP@10 при δ с фолда 0 положителен с бутстреп-интервалом выше нуля (или хотя бы положителен и совпадает по знаку с фолдом 0 — тогда осторожно) и отказ не падает больше, чем даёт mAP. Из годных — самый дешёвый на инференсе (голова раньше CLIP).

## Выводы
- **Решение:** `clip_hard`, δ = 0,07 — принят осторожно, по заранее записанному правилу: на фолде 4 прирост положителен и совпадает по знаку с фолдом 0, но интервал задевает ноль. На фолд 4 перенеслась примерно половина прироста фолда 0 (+0,0042 из +0,0091) — ровно та доля оптимизма, которую давал подбор δ на одном фолде. Кривая на фолде 4 положительна во всём диапазоне δ от 0,01 до 0,10 с максимумом 0,06–0,07, то есть δ = 0,07 не случаен. Ожидание на тесте — около +0,004 mAP@10, ≈ +0,2 балла.
- **Цена:** на инференсе нужен CLIP ViT-B/16 (LAION-2B) для ракурса запроса — ещё один проход небольшой модели, ~0,2 ГБ весов в fp16; ракурсы галереи считаются при индексации. Задержку на A5000 нужно измерить: бюджет полного балла — 40 мс, итоговая конфигурация сейчас ~19 мс.
- **Голова на эмбеддинге не годится:** 72% совпадения с CLIP — слишком шумный ракурс; прирост +0,0017 в шуме. Если CLIP на инференсе окажется дорог, следующая проба — голова на токенах патчей, которые реранкер уже считает (в них ракурс есть, в итоговом эмбеддинге его почти нет).
- **Фолд 4:** это второй объявленный просмотр после EXP-171; подбирать на нём что-либо дальше нельзя.
