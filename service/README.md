# Falcon · Визуальный поиск

Самостоятельный сервис в репозитории `yslfalcon`: рабочее место оператора, HTTP API, галереи с версиями, фоновые задания, история, сравнение изображений и экспорт.

**Обученная модель намеренно не подключена.** Работает явно обозначенная заглушка. Она позволяет проверить весь сервисный сценарий, но не подтверждает идентичность автомобилей и не сообщает качество ReID. Веса, GPU и исследовательские зависимости для запуска не нужны.

## Запуск одной командой

Нужны Docker с Compose v2, Python 3.12+ для вспомогательных команд и свободный порт 8090. Первичная сборка загружает зависимости; уже собранное приложение работает без внешнего интернета.

```bash
cd service
./scripts/start.sh
```

Открыть **http://localhost:8090**. Локальный токен входа находится в `service/.local/access-token.txt`. Скрипт создаёт случайные секреты в `.env` с правами `0600`; повторный запуск сохраняет их. Содержимое `.env` и `.local/` исключено из Git и поставки.

В Compose пять отдельных процессов: `web`, `api`, `worker`, `runtime`, `postgres`. Наружу опубликован только web на `127.0.0.1`. Все шрифты, скрипты и API-документация локальные.

## Рабочий сценарий

1. Войти и открыть «Галереи». Создать галерею, загрузить JPEG/PNG.
2. При необходимости приложить JSON-манифест с BBox. Дождаться завершения импорта и активировать подготовленную версию.
3. В «Поиске» выбрать галерею, загрузить запрос, задать рамку численно или на изображении.
4. Открыть кандидата для крупного сравнения. Сохранить отдельное заключение оператора или запустить демонстрацию карты влияния заглушки.
5. Выгрузить PDF, JSON или CSV. В истории открыть прежний результат либо воспроизвести его на сохранённой версии.

Пример манифеста импорта:

```json
{
  "frame-001.jpg": {"bbox": [320, 180, 640, 420], "external_id": "observation-001"},
  "frame-002.png": {"bbox": [100, 90, 800, 600]}
}
```

Координаты — `x, y, width, height` в пикселях исходного изображения. При отсутствии BBox используется весь кадр, что явно отмечается. Рамки, частично выходящие за край, обрезаются по границе; полностью внешние и некорректные рамки отклоняются. EXIF-поворот требуется нормализовать вместе с координатами до загрузки. Импорт — полная новая версия галереи, а не добавление в активный снимок.

## Что работает

- Аутентификация интеграций, браузерные сессии, CSRF, роли viewer/operator/admin и изоляция workspace.
- Проверка изображений, размеров и BBox; безопасное хранение оригиналов.
- Фоновые импорты, версии галерей, атомарная активация с проверкой ожидаемой версии.
- Независимые запросы, сохранение результата, устойчивый Idempotency-Key и воспроизведение старого snapshot.
- Сравнение пары, отдельные заключения оператора, асинхронная диагностическая карта.
- Скачиваемые PDF/JSON/CSV из сохранённого результата с версиями и контрольными суммами.
- Реальные статусы заданий и сервисных зависимостей, локальный OpenAPI.
- Ограниченные повторные попытки worker; восстановление после прерывания и защита от записи устаревшим исполнителем.

Заглушка всегда оставляет `accepted_candidates` пустым и возвращает `calibration_unavailable`. Числовое сходство — техническая характеристика заглушки. Категории принятия и отказа предусмотрены интерфейсом ядра и проверяются на синтетических тестовых примерах; боевой порог не установлен.

## API

Локальная документация: `/docs`, спецификация: `/api/v1/openapi.json`. Все предметные методы требуют bearer token либо сессию; health и описание контракта доступны без токена. Основные операции перечислены в [CONTRACT.md](CONTRACT.md).

```bash
curl --header "Authorization: Bearer ${FALCON_ACCESS_TOKEN}" \
  http://localhost:8090/api/v1/galleries
```

Для cookie-запросов браузер передаёт разрешённый Origin и `X-CSRF-Token`, полученный при входе. Для прямого API используется bearer. Токены в URL не принимаются. Повтор поиска с тем же ключом и другим содержимым получает конфликт; обновление галереи не меняет закреплённую версию уже начатого запроса.

## Локальная разработка

```bash
cd service
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
npm --prefix frontend ci
```

`FALCON_DATABASE_URL` может указывать на SQLite для локальной разработки и тестов; Compose использует PostgreSQL. Настройки задаются через окружение с префиксом `FALCON_`. В локальном процессе `.env` автоматически не импортируется: это Compose-конфигурация. Для запуска отдельных процессов передайте переменные явно.

```bash
PYTHONPATH=backend .venv/bin/uvicorn falcon_service.app:app --host 127.0.0.1 --port 8000
PYTHONPATH=backend .venv/bin/python -m falcon_service.worker
npm --prefix frontend run dev -- --host 127.0.0.1
```

Эти команды требуют настроенных `FALCON_AUTH_TOKENS`, `FALCON_ALLOWED_ORIGINS` для адреса Vite и `FALCON_COOKIE_SECURE=false` при локальном HTTP. Для повседневного запуска предпочтителен Compose, который передаёт согласованную конфигурацию всем процессам.

## Проверки

```bash
.venv/bin/python -m pytest
.venv/bin/ruff check backend tests scripts
.venv/bin/ruff format --check backend tests scripts
npm --prefix frontend test
npm --prefix frontend run build
npm --prefix frontend run format:check
docker compose config --quiet
.venv/bin/python scripts/smoke.py
```

`smoke.py` обращается к работающему стеку и создаёт отдельную QA-галерею с синтетическими рисунками. Проверяются импорт, активация, запрос, повтор, смена версии, replay, заключение, объяснение, три экспорта и закрытость изображений без авторизации. Этот прогон не является оценкой распознавания.

CI находится в `../.github/workflows/service.yml`: Python-проверки, frontend-проверки, аудит зависимостей, сборка Compose и HTTP smoke. Фактические локальные результаты — в [docs/VALIDATION.md](docs/VALIDATION.md).

## Автономная поставка

После сборки всех образов:

```bash
python3 scripts/package_offline.py
```

В `delivery/falcon-offline/` появляются исходники сервиса, архив Docker-образов, manifest с hashes и `start.sh`. На совместимой машине с Docker, Compose и Python:

```bash
./start.sh
```

Проверяется целостность, загружаются локальные образы и выполняется запуск с `--no-build --pull never`. Комплект не содержит текущие секреты, загруженные изображения, БД или веса. Архитектура образов должна соответствовать целевой машине; для Linux x86_64 комплект следует собирать под `linux/amd64`.

При обновлении существующего развёртывания перенесите прежний `.env` и `.local/access-token.txt` в `source/` нового комплекта до запуска: пароль должен соответствовать сохранённому volume PostgreSQL. Для отдельной установки используйте другое `COMPOSE_PROJECT_NAME` и `FALCON_WEB_PORT`; задайте соответствующие адреса в `FALCON_ALLOWED_ORIGINS`.

## Конфигурация и сопровождение

Основные параметры и имена секретов описаны в [deploy/envs/default/values.yaml](deploy/envs/default/values.yaml). Значения секретов хранятся локально в `.env` либо в системе секретов выбранной инфраструктуры.

Состояние: `docker compose ps`. Логи: `docker compose logs --tail=100 api worker runtime`. Остановка с сохранением данных: `docker compose down`. Named volumes сохраняют БД и артефакты. Первичная схема создаётся автоматически, штатных операций удаления данных в интерфейсе этого выпуска нет.

Перед обновлением сохраняйте согласованную резервную копию PostgreSQL и volume артефактов. Для изменения схемы требуется отдельная миграция. Откат образа допустим только при совместимой схеме; повторная активация прежней галереи выполняется штатной операцией версий.
