# Модель внутри runtime-образа

Каталог собирает GPU runtime с обученной моделью (`deploy/runtime.Dockerfile`). Сервисный код модели не
импортирует: адаптер `RepositoryEncoder` подгружает этот каталог только внутри runtime-образа, а API, worker и web
остаются без PyTorch.

| Файл | Что это |
|---|---|
| `reid/` | инференс-код модели: вырезка по рамке, башня SigLIP 2, fp16, голова ракурса |
| `final_model.yaml` | сдаваемая конфигурация: архитектура, имена файлов весов, порог отказа, δ поправки на ракурс |
| `weights.json` | откуда брать веса и их sha256 |
| `requirements-model.txt` | зависимости модели, torch с CUDA 12.6 |
| `fetch_weights.py` | запекает веса в образ при сборке и пишет `runtime-bundle.json` |

Исходная копия, кроме `fetch_weights.py`, взята из ветки `main` (коммит `94fdf76`). Локальное структурное изменение:
`reid/models.py` сохраняет прежние импорты, а определения без изменения формул и параметров перенесены в
`reid/_model_backbones.py`, `reid/_model_pooling.py`, `reid/_model_checkpoints.py` и `reid/_model_heads.py`.
Имена классов для сериализации остаются в `reid.models`; runtime по-прежнему не содержит исследовательскую ветку
FastReID. Остальные файлы исходной копии не менялись; `SOURCE.sha256` содержит контрольные суммы текущих файлов,
включая новые модули. При обновлении модели из `main` нужно согласованно обновлять обе структуры и манифест,
чтобы сервис и сабмит не разошлись.
