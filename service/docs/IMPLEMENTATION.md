# Каскад реализации

Этот документ связывает пользовательский сценарий, код и требования к сервису. Инструкции запуска находятся в [README](../README.md), решения по развёртыванию — в [ARCHITECTURE](ARCHITECTURE.md). Результаты конкретных прогонов фиксируются отдельно в `VALIDATION.md`.

**Граница выпуска:** инфраструктура, хранение, задания и HTTP-взаимодействие работают с настоящими данными пользователя; вместо обученной ReID-модели подключена явная заглушка. Она проверяет путь обработки и никогда не подтверждает совпадение автомобилей. Этот выпуск не демонстрирует качество распознавания или конкурсную производительность.

## От действия оператора до сохранённого результата

| Шаг | Реализованный путь | Гарантия |
|---|---|---|
| Вход | React → `/auth/session` → хэш сессии в БД | HttpOnly cookie; изменяющие запросы проверяют Origin и CSRF. Интеграции используют bearer token. |
| Полная галерея из CSV | CSV → сохранённая сессия → проверяемые порции изображений → статус принятых/отсутствующих файлов → `finalize` → версия `preparing` и durable job → worker → признаки в БД и наблюдения → версия `ready` | Сессия переживает перезапуск, одинаковые повторы безопасны, финализация создаёт ровно один job/снимок. Ни порция файлов, ни сбой вычисления не публикуют частичную галерею. Активация выполняется отдельно. |
| Прежний импорт | Один multipart с файлами и необязательным JSON manifest → проверка всей порции → тот же worker | Сохранена совместимость небольших загрузок. Этот маршрут не является протоколом возобновления большой галереи. |
| Активация | Выбранная версия и `expected_active_version_id` → проверка совместимости → атомарное обновление указателя | Устаревшее действие получает конфликт. Уже начатые поиски сохраняют свою версию. |
| Поиск | Проверка входа → сохранение запроса и закрепление версии → признак → ранжирование → неизменяемый результат | Idempotency-Key переживает перезапуск. Запрос не зависит от соседних запросов; техническая ошибка не становится отказом. |
| Проверка пары | Сохранённая выдача → оригиналы/кропы → отдельное заключение оператора | Заключение не изменяет ранги, оценки и решение алгоритма. |
| Объяснение | Выбранный кандидат → фоновое задание → перекрытие областей → карта чувствительности заглушки | Карта имеет метод и ограничения. Исходные изображения и основной результат не изменяются. |
| Экспорт | Сохранённый поиск и заключения → фоновое задание → PDF/JSON/CSV → защищённое скачивание | Экспорт содержит версии; JSON/PDF также содержат предупреждение preview и хэши изображений. Хэш готового файла возвращает задание; чужой workspace не получает файл по ссылке. |
| Воспроизведение | История → первоначальные изображение, BBox, версия и политика → новый результат | Используется прежний снимок галереи; недоступность необходимого алгоритма возвращается явно. |

Импорт создаёт **полную замещающую версию** галереи. Число наблюдений не называется числом уникальных автомобилей: сервис не объединяет их в идентичности автоматически.

## Карта кода

|---|---|---|
| Композиция приложения | [app.py](../backend/falcon_service/app.py), [config.py](../backend/falcon_service/config.py) | Настройки, зависимости, жизненный цикл, ограничения запросов, обработка ошибок и локальная документация. |

Алгоритм ранжирования здесь не реализуется. |
| Каталог | [catalog.py](../backend/falcon_service/catalog.py), [models.py](../backend/falcon_service/models.py), [db.py](../backend/falcon_service/db.py) | Версии, публикация и транзакционные ограничения. PostgreSQL в Compose, SQLite для локальной разработки и тестов. |
| Возобновляемый импорт | [imports.py](../backend/falcon_service/imports.py), [routes/galleries.py](../backend/falcon_service/routes/galleries.py) | Проверка официального CSV, соответствие файлов, долговечные сессии и атомарная финализация. |
| Признаки галереи | [features.py](../backend/falcon_service/features.py) | `FeatureStore`: числовые массивы в БД, проверка целостности/модели и перенос старых NPZ при первом чтении. |
| Сценарий поиска | [search.py](../backend/falcon_service/search.py) | Закрепление контекста, долговечная идемпотентность, выполнение и сохранение результата. |
| Вычислительная граница | [inference/](../backend/falcon_service/inference/), [runtime.py](../backend/falcon_service/runtime.py), [model_runtime.py](../backend/falcon_service/model_runtime.py) | `Encoder`, `FeatureBundle`, проверка изображений, ранжирование и объяснение. В Compose используется отдельный HTTP runtime с заглушкой. |
| Фоновые операции | [jobs.py](../backend/falcon_service/jobs.py), [leases.py](../backend/falcon_service/leases.py), [worker.py](../backend/falcon_service/worker.py) | Импорт, объяснение и отчёты; аренда задания, продление, ограниченные повторы и защита публикации от старого исполнителя. |
| Артефакты | [storage.py](../backend/falcon_service/storage.py), [exports.py](../backend/falcon_service/exports.py) | Серверные пути оригиналов и отчётов; чтение старых файлов признаков для переноса. Новые признаки сохраняются через `FeatureStore` в БД. |
| Интерфейс | [pages/](../frontend/src/pages/), [components/](../frontend/src/components/), [imports.ts](../frontend/src/imports.ts), [api.ts](../frontend/src/api.ts), [domain.ts](../frontend/src/domain.ts) | Поиск, BBox, сравнение, галереи, CSV-проверка, порционная загрузка/возобновление, история и эксплуатационные экраны. Результат ранжирования приходит от API. |
| Поставка и проверка | [scripts/](../scripts/), [tests/](../tests/), [CONTRACT.md](../CONTRACT.md) | Запуск, HTTP smoke, автономный комплект, проверки поведения и согласованный интерфейс. |

Основная точка расширения для будущей модели — `Encoder`. Предметные сценарии получают зависимости явно: `Database`, `ArtifactStore`, `EncoderRuntime`; `FeatureStore` объединяет доступ к БД и старым файлам признаков. SQL-персистентность сосредоточена в серверных модулях; клиент и вычислительное ядро не управляют транзакциями каталога.

Очередь находится в БД. На финальной записи worker проверяет свой claim token условным SQL-обновлением внутри той же транзакции, где публикует данные. Это обеспечивает защиту владения и в PostgreSQL, и в SQLite, где `SELECT FOR UPDATE` не создаёт нужной блокировки. Описание восстановления — в [ARCHITECTURE](ARCHITECTURE.md).

## Что из ТЗ и целевого продукта закрыто

«Реализовано» ниже означает наличие соответствующего сервисного поведения. Приёмку качества модели и проверку на стенде организаторов это не заменяет.

| Требование или возможность | Состояние выпуска |
|---|---|
| JPEG/PNG и заданный BBox | Реализовано: ограничения размера/разрешения, проверка координат, явный полный кадр без BBox. EXIF-поворот с неизвестным преобразованием рамки отклоняется. |
| CSV `image_id,x,y,w,h` и полная галерея | Реализованы сессии до 10 000 строк и порции до 100 файлов при стандартных настройках. Прогресс сохраняется на сервере; перезапуск не требует загрузки принятых файлов заново. Точные ограничения приведены в [ARCHITECTURE](ARCHITECTURE.md). |
| Сохранение эмбеддингов галереи в БД | Реализовано в `feature_artifacts`: бинарные числовые массивы, модель, размерность, тип и контрольная сумма. Публикация признаков и наблюдений атомарна; новые снимки не зависят от NPZ на диске. |
| Фиксированный нормализованный признак и ранжирование | Контракт реализован на RGB-заглушке; настоящее представление автомобиля предстоит подключить. |
| Уверенное совпадение либо отказ | Ядро предусматривает отдельное решение и проверку политики. В рабочей заглушке всегда `calibration_unavailable`, принятых кандидатов нет. Обоснованный боевой порог отсутствует. |
| Независимая обработка запросов | Реализована: используются текущий запрос и закреплённая галерея. Камеры, номера, география и соседние запросы не подаются в алгоритм. |
| Браузерный клиент, сервер, БД и документированный API | Реализованы React/TypeScript, Python/FastAPI, PostgreSQL, OpenAPI и отдельные процессы web/api/worker/runtime. |
| Запуск в Docker и автономная поставка | Подготовлены Compose и упаковка локальных образов с проверкой целостности. После первичной сборки внешний интернет для приложения не требуется. |
| Сравнение и объяснимость | Реализованы сравнение изображений и асинхронная occlusion-карта. Карта объясняет дескриптор заглушки; она не доказывает признаки идентичности автомобиля. |
| История, отчёт и воспроизводимость | Реализованы сохранение, закреплённые версии, replay, отдельные заключения и PDF/JSON/CSV. Пагинация есть у истории поиска, списка галерей и списка заданий; списки версий и сессий импорта возвращаются целиком. |
| Обновление галереи без изменения прошлых результатов | Реализованы подготовка новой версии и явное переключение. Автоматическое удаление старых версий отсутствует. |
| Отказоустойчивые фоновые операции | Реализованы сохранение задания, аренда, повторы и атомарная публикация. Отказоустойчивый кластер нескольких узлов этим выпуском не проверен. |
| Три конкурсных файла | [CLI](../backend/falcon_service/cli.py) позволяет репетировать форматы на preview и помечает результат `submission_ready: false`. Это не готовый конкурсный сабмит. |
| Качество, калибровка, веса и производительность на GPU | Не реализуются в текущем задании. Метрики mAP/F1/TNR, заявленные миллисекунды/FPS и соответствие будущего комплекта весов лимиту требуют отдельной проверки с настоящей моделью. |
| Миллион наблюдений и ANN | Не заявляются. Сейчас признаки читаются в память и выполняется точный поиск; опциональный интерфейс индекса не является доказательством такого масштаба. |
| Лаборатория ошибок и безопасное обновление модели | Экраны статуса и границы интеграции подготовлены. Разбор качества по размеченным срезам, сравнение моделей в тени и переключение настоящих model bundles ещё предстоят. |

## Проверки импорта и хранения

[test_import_sessions.py](../tests/test_import_sessions.py) проходит загрузку 750 изображений через публичный API порциями, перезапуск/возобновление, повтор порции, конкурентную финализацию в один снимок, явную активацию и последующий поиск. Отдельно проверяются ошибки и неоднозначности CSV, большие числовые экспоненты, ограничение порции, конфликт подмены файла, атомарность неуспешной порции, clipping BBox и изоляция workspace.

[test_feature_store.py](../tests/test_feature_store.py) проверяет поиск, replay и отчёт после удаления файлового кеша и перезапуска, добавление отсутствующей таблицы к старой схеме, перенос старых NPZ, отказ при повреждённой записи БД и отсутствие частичных признаков при сбое worker. Прежний multipart-сценарий остаётся в [test_backend.py](../tests/test_backend.py). Число тестов, команды и подтверждённые проверки PostgreSQL/Docker записываются только в [VALIDATION](VALIDATION.md).

## Ограничения и следующие задачи команды

1. **Проверить операторский интерфейс на реальных изображениях.** Пройти сценарии загрузки, редактирования BBox, смены галереи, крупного сравнения, отказа/ошибки, клавиатурной навигации и скачивания отчётов в целевых браузерах. Проверка API и сборка frontend не заменяют визуальную приёмку.
2. **Подключить обученную модель отдельным изменением.** Реализовать адаптер, закрепить веса и предобработку, проверить численный паритет, размер весов, независимость запросов и калибровку на согласованном протоколе. Затем измерить полный цикл на требуемом GPU; задержки текущей заглушки для этого непригодны.
3. **Сохранять совместимость обновления данных.** Этот выпуск автоматически добавляет `feature_artifacts`, `import_sessions`, `import_items` через `create_all`, не изменяя существующие колонки. Старые NPZ обязательны до переноса всех нужных версий при их чтении. Возврат только старого Docker-образа не поддерживает новые признаки, существующие лишь в БД; необходима согласованная резервная копия или отдельный совместимый перенос. Порядок и ограничения описаны в [ARCHITECTURE](ARCHITECTURE.md). Для будущих изменений колонок нужны версионированные миграции и проверка восстановления.
4. **Добавить управляемое хранение и очистку.** При прерывании до фиксации ссылки в БД могут остаться осиротевшие файлы. Автоматического GC, сроков хранения и удаления версий пока нет. Очистка должна учитывать ссылки сохранённых поисков и отчётов.
5. **Подтвердить масштаб отдельным стендом.** Для больших галерей потребуются индекс, загрузка/кэш признаков и контроль расхода памяти. ANN, полнота поиска относительно точного метода, задержки под конкурирующей нагрузкой и обновление индекса должны измеряться на реальном размере данных.

Приоритет следующего этапа — проверенное рабочее место оператора и корректное подключение модели к уже согласованному интерфейсу. Новые сервисы, брокеры и индексы стоит добавлять под измеренное требование, сохраняя единую семантику версий, решения и воспроизведения.
