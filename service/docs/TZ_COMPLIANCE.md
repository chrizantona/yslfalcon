# Сверка сервиса с ТЗ

Основание: «7. Фалькон Тех (1).pdf», §3–13, уточнения `eda/KEY_FINDINGS.md` и корневой `AGENTS.md`. Дата сверки: 21 сентября 2026. Проверки конкретного выпуска: [VALIDATION](VALIDATION.md).

**Область работ:** сервис на отдельной ветке `feature/falcon-service`. Настоящая ReID-модель намеренно не подключена по требованию пользователя. Поэтому «сервис реализован» не означает «все конкурсные требования выполнены».

## Что исправляет этот этап

1. Ограничение единичного импорта 500 файлами больше не препятствует загрузке полной галереи: большие наборы идут через сессию и части, затем публикуются одной версией. Старый простой импорт сохранён для небольших наборов.
2. База хранит сами признаки, а не только путь к NPZ. Старые данные остаются совместимыми через перенос при чтении; повреждённый DB-артефакт не маскируется запасным файлом.
3. OpenAPI содержит реальные схемы успешных и ошибочных ответов; браузерная документация работает без CDN.
4. Offline-комплект проверяет платформу образов и задаёт изолированную сеть. Проверка формата сдачи отделена от оценки модели.

## Границы дальнейших обещаний

До подключения настоящей модели не заявлять качество ReID, откалиброванную уверенность, официальный отказ, выполнение целевого FPS или итоговую конкурсную готовность. Не использовать распознавание номеров, камеры, порядок CSV, image_id или хэши как признаки ранжирования. Не добавлять детекцию и трекинг: они исключены из задачи.

После сервисной приёмки выбрать три усиления из [JURY_FEATURES](JURY_FEATURES.md), подготовить финальный комплект модели отдельной задачей и провести репетицию на целевой машине. Приоритеты функций следуют реальным весам §9; красивый интерфейс не заменяет 75% оценки, связанных с качеством, скоростью и отказом модели.
