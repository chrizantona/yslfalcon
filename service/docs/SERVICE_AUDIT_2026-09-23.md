# Аудит сервиса и killer features

Дата: 23 сентября 2026. Основание: ТЗ «Фалькон Тех», текущая ветка `feature/falcon-service` и
фактически запущенный preview-стенд. Модель, её качество и развёртывание не входят в этот аудит.

## Итог

Сервисная основа сильнее обычного конкурсного демо: есть отдельные web/API/worker/runtime/PostgreSQL,
неизменяемые версии галереи, durable jobs, replay, заключения оператора, четыре экспорта, локальный
OpenAPI, workspace isolation и offline-поставка. После этого этапа внешний GPU runtime подключается
через узкий проверяемый контракт, не загрязняя API модельными зависимостями.

Главный риск защиты — не отсутствие ещё одного dashboard, а недостаточно собранная история показа.
Сейчас сильные функции распределены по разным разделам. Жюри должно увидеть один законченный кейс:
кадр и BBox → решение/отказ → проверка пары → заключение → доказуемый экспорт → воспроизведение на
той же версии.

## Что уже можно показывать честно

| Возможность | Состояние | Ценность на защите |
|---|---|---|
| Кадр + интерактивный/числовой BBox | Работает | Сразу связывает UI с форматом задачи |
| Полный CSV-импорт частями | Работает, возобновляется | Показывает не игрушечную загрузку |
| Неизменяемые версии и явная активация | Работает | Сильная инженерная история |
| Поиск, крупное сравнение и top-N | Работает на preview | Сценарий реален, ранги нельзя называть ReID |
| Явный `calibration_unavailable` | Работает | Ошибка инфраструктуры не маскируется под отказ |
| Заключение оператора | Работает отдельно от модели | Аудируемое human-in-the-loop решение |
| History + replay закреплённого snapshot | Работает | Воспроизводимость решения |
| Экспертная доска 3-up + координатные пометки | Работает на preview | Главный визуальный сценарий без ложной объяснимости |

## Пробелы по требованиям и презентации

1. **P0 перед публичным хостингом:** UI не имеет удалённого входа. Auto-login намеренно работает
   только на localhost. Нельзя публиковать admin workspace или обходить Origin-проверку в reverse
   proxy; нужен небольшой token-login/одноразовый demo-user flow с HTTPS-cookie.
2. **P0 перед защитой:** отсутствует визуальная браузерная приёмка текущего дизайна на реальных
   изображениях. Unit/build/HTTP зелёные, но клики, zoom, pointer, мобильная раскладка и анимация не
   проверены из-за недоступного встроенного браузера.
3. **P0 после передачи модели:** эталонный parity test, production calibration и официальный
   `reid.benchmark`; preview-тайминги и heatmap не являются доказательством модели.
4. **P2:** нет подлинного атласа FP/FN с GT и переходом от метрики к изображениям.
5. **P2:** ANN на миллион не реализован и не должен имитироваться.

Три прежних P1 закрыты после аудита: добавлены экспертная доска, offline-дело и diff версий. Их
визуальная браузерная приёмка остаётся частью общего P0 из пункта 2.

## Что сильнее всего выглядит визуально

### 1. Экспертная доска из трёх кадров — главный visual wow

Слева запрос, по центру top-1, справа самый похожий конкурент. На каждом — оригинал/кроп,
синхронный zoom, BBox и ручные координатные выноски «совпадает», «противоречит», «неразличимо».
Справа остаётся короткое заключение. Доска сохраняется и открывается из истории.

Почему это работает: большие фотографии занимают экран, жюри понимает задачу без объяснений, а
человеческий анализ не выдаётся за модельную интерпретируемость. Это развитие уже существующего
comparison, а не новый декоративный раздел.

### 2. «Скачать дело» — самый запоминающийся продуктовый артефакт

Одна кнопка выдаёт ZIP: оригиналы, кропы, BBox, сохранённые ранги, версии, заключения, PDF, локальный
HTML-viewer и manifest SHA-256. Затем на сцене архив открывается без сервера; изменение копии одного
файла даёт точную ошибку verifier. Визуально проще экспертной доски, но сильнее всего доказывает
готовность продукта, автономность и воспроизводимость.

### 3. Hot-swap галереи с неизменяемой историей — инженерный surprise

Открыть результат на v1, показать diff подготовленной v2, активировать её, повторить запрос и рядом
оставить оба результата. Replay старого результата снова использует v1. Это редкая для хакатона
демонстрация: не просто поиск, а безопасная эксплуатация меняющейся базы.

## Приоритет реализации

| Функция | Визуальный эффект | Доверие | Без модели | Оценка | Приоритет |
|---|---:|---:|---:|---:|---:|
| Экспертная доска 3-up | 5/5 | 4/5 | Да | Реализовано | A |
| Единое offline-дело | 4/5 | 5/5 | Да | Реализовано | A |
| Diff и сравнение версий | 4/5 | 5/5 | Да | Реализовано | A |
| Полезная диагностика входа/отказа | 3/5 | 4/5 | Частично | 2–3 дня | B |
| Атлас настоящих ошибок | 4/5 | 5/5 | Нужны GT-артефакты | 3–4 дня | B |
| Live fault recovery | 3/5 | 5/5 | Да | 2 дня | B |
| ANN million стенд | 3/5 | 5/5 | Нужен реальный индекс | 4–6 дней | C |

Все три функции приоритета A теперь реализованы поверх существующих сущностей без изменения
основного визуального языка. Следующий шаг — браузерная приёмка и сборка репетиционного набора.

## Сценарий защиты на четыре минуты

1. **0:00–0:35.** Загрузить кадр, поправить BBox, запустить поиск. Одной фразой: запросы независимы,
   галерея закреплена версией.
2. **0:35–1:25.** Открыть экспертную доску, сравнить top-1 и конкурента, поставить две выноски,
   сохранить отдельное заключение.
3. **1:25–2:00.** Скачать offline-дело, открыть локальный viewer и manifest.
4. **2:00–2:55.** Показать diff v1→v2, активировать v2, выполнить связанный новый поиск; старый
   результат остаётся на v1.
5. **2:55–3:30.** Открыть System/Quality: фактический model ID, CUDA/precision/вес, очередь и
   измеренные timings с явной оговоркой, что это не официальный benchmark.
6. **3:30–4:00.** Открыть OpenAPI и назвать три гарантии: отказ не равен сбою, история неизменяема,
   сервис работает offline.

Заранее подготовленные картинки допустимы только как разрешённый демонстрационный набор. Нельзя
показывать придуманные метрики, камеры, heatmap настоящей модели до её подключения или «миллион» без
фактического индекса и отчёта.
