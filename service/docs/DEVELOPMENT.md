# Разработка и качество кода

Предметная логика живёт в Python-модулях, HTTP-маршруты связывают контракт с операциями, а интерфейс работает через типизированный API-клиент. Компоненты не выполняют запросы к БД и не вычисляют решение алгоритма. Единственная граница будущей модели — интерфейс encoder; текущий выпуск использует заглушку.

Проверки и команды находятся в [README](../README.md), фактические результаты — в [VALIDATION](VALIDATION.md). Изменения поведения проверяются через наблюдаемый результат: изоляцию рабочего пространства, сохранение версии, повтор запроса, конфликт активации, восстановление задания. Копирование реализации в тесты не заменяет эти проверки.

По запросу пользователя локально установлены универсальные навыки разработки:

| Источник | Навык | Назначение |
| --- | --- | --- |
| [obra/superpowers](https://github.com/obra/superpowers) | `systematic-debugging` | Воспроизведение причины ошибки перед исправлением |
| [obra/superpowers](https://github.com/obra/superpowers) | `verification-before-completion` | Подтверждение результата свежими проверками |
| [obra/superpowers](https://github.com/obra/superpowers) | `requesting-code-review` | Независимое ревью изменений |
| [mattpocock/skills](https://github.com/mattpocock/skills) | `codebase-design` | Простые интерфейсы модулей и локализация сложности |
| [mattpocock/skills](https://github.com/mattpocock/skills) | `tdd` | Проверка поведения через публичные границы |

Это инструменты локальной разработки, не зависимости сервиса. Они находятся в пользовательском каталоге навыков Codex и не требуются для сборки приложения. Для появления новых навыков в каталоге следующей сессии потребуется перезапуск Codex.
