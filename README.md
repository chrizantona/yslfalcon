# yslfalcon — повторная идентификация автомобилей без номеров

Решение задачи «Фалькон Тех», ЛЦТ 2026: по кадру 1920×1080 и рамке автомобиля найти ту же машину среди кадров
с других камер и выдать десять кандидатов — либо отказаться от ответа, если машины в галерее нет.

В `main` лежит только то, что участвует в сдаче: код инференса, конфиг финальной модели и сборка образа.
Все 208 экспериментов, их карточки, реестр, протокол валидации и код обучения — в ветке
[`experiments`](../../tree/experiments).

## Что сдаётся

Одна модель, один прямой проход на автомобиль:

```
кадр 1920×1080 + рамка
  → вырезка по рамке, длинная сторона ≤ 512 px
  → сжатие до 224×224, нормализация SigLIP
  → SigLIP 2 So400m/14 (27 блоков, ширина 1152, 16×16 = 256 патч-токенов), fp16
  → attention pooling → BNNeck → L2 → эмбеддинг 1152        ─┐
  → среднее патч-токенов → Linear 1152×3 → ракурс           ─┤
                                                             ▼
  поиск: cos(q, g) − 0,07 · [ракурс совпал] → top-10 → submission.csv
  отказ: z-оценка топ-1 (без штрафа) ≥ 7,0828 → строка в candidates.csv
```

- **Башня** — публичные веса `ViT-SO400M-14-SigLIP2` (webli), дообученные в два этапа: претрейн на VERI-Wild test,
  затем все пять фолдов обучающей выборки с ArcFace (imprinting центров) + SupCon + batch-hard triplet.
- **Суп** — равновесное усреднение весов трёх сидов: одна модель, без роста времени и размера.
- **Поправка на ракурс** — штраф кандидату, снятому с той же стороны, что запрос: 77% потерянного AP приходится
  на смену ракурса, а неверный первый ответ совпадает с запросом по ракурсу в 80% случаев против 37% у случайного
  кадра. Голова ракурса — матрица 1152×3 на токене, который и так посчитан; второй сети не нужно.
- **Отказ** — по z-оценке лучшего кандидата относительно распределения сходств этого запроса; порог получен
  калибровкой leave-one-fold-out на пяти фолдах.

Ни номеров, ни `camera_id`, ни query expansion, ни кластеризации по запросам — потоковый протокол соблюдён.

## Результаты

Отложенный фолд 4 (1 112 запросов, одна галерея как на тесте, официальные определения метрик):

| | Значение |
|---|---|
| mAP@10 | **0,9000** |
| Балл отказа (0,7·F1 + 0,3·TNR) | **0,9562** (F1 0,9663, TNR 0,9327) |
| 45·mAP@10 + 10·отказ | **50,06** из 55 |

Эта цифра измерена у модели, обученной на фолдах 0–3. Сдаётся та же конфигурация, дообученная ещё и на фолде 4;
проверить её нельзя по построению, по кривой обучения ожидается ещё +0,008 mAP@10.

Скорость на RTX A5000 (методика организаторов: полный цикл на одно ТС, медиана 300 прогонов после 50 прогревов;
FPS — лучший из батчей 1/8/16/32):

| | Порог полного балла | Наше значение |
|---|---|---|
| Время на одно ТС | ≤ 40 мс | **18,94 мс** |
| Лучший FPS | ≥ 100 | **125,5** |
| Суммарный размер весов | ≤ 2 ГБ | **1 718 МБ** + 15 КБ голова ракурса |
| Пиковый VRAM | — | 1 211 МБ |

## Как запустить

Датасет монтируется в `/data`, результат появляется в `artifacts/final/submission/`:

```bash
docker compose up --build        # образ офлайн: веса вшиты в слой, HF_HUB_OFFLINE=1
```

Без Docker:

```bash
pip install -r requirements-inference.txt
PYTHONPATH=src python -m reid.submit --data-config configs/data.yaml --config configs/final_model.yaml
```

На выходе три файла в формате организаторов: `submission.csv` (10 кандидатов на запрос, без заголовка),
`candidates.csv` (одна строка на отвеченный запрос) и `embeddings.npy` (float32, сначала все query, затем gallery).
Проверены их собственными загрузчиками из `evaluate.py`.

## Что где лежит

| Путь | Что это |
|---|---|
| `src/reid/submit.py` | сборка сабмита: эмбеддинги, поправка на ракурс, порог отказа |
| `src/reid/inference.py` | загрузка обученного энкодера без обращения к публичным весам |
| `src/reid/view_head.py` | голова ракурса: обучение, сохранение, применение штрафа |
| `src/reid/models.py`, `embed.py`, `data.py` | башня, BNNeck, вырезка по рамке, батчевый инференс |
| `src/reid/benchmark.py` | замер по методике организаторов; `InferencePrecision` — fp16-веса и CUDA graph |
| `src/reid/metrics.py` | mAP@10, режим отказа и bootstrap в точности как в `evaluate.py` |
| `configs/final_model.yaml` | сдаваемая конфигурация целиком |
| `DATA.md` | источники данных и весов с sha256, как повторить с нуля |

## Исследование

Ветка [`experiments`](../../tree/experiments) — 208 экспериментов с карточками и реестром
(`experiments/registry_val_v2.csv`). Правила: одно изменение за эксперимент, три сида на точку, решение по парному
bootstrap по машинам, отложенный фолд открывается только по заранее записанному правилу. Самое полезное там —
список того, что **не** сработало: маски SAM, подмена фона, цветовые и ночные аугментации, AFEM, OSNet,
sub-centre ArcFace, псевдоразметка, дистилляция, 60 эпох.

## Ограничения

- Модель обучена на всех пяти фолдах, поэтому её собственного замера нет — есть замер предыдущей конфигурации
  на нетронутом фолде 4 и кривая обучения.
- Порог отказа откалиброван на пяти фолдах вне выборки; на публичном тесте он отказывает в 5,5% запросов.
  Если в закрытом тесте «запрос без пары» устроен иначе (машина остаётся в галерее, но только с камеры запроса),
  z-оценка к таким запросам слепа — измерено, записано в карточке EXP-207 ветки `experiments`.
- `Dockerfile` пока тянет веса прошлой модели: адрес и sha256 финальных весов нужно подставить после публикации.
