# yslfalcon — повторная идентификация автомобилей без номеров

Решение задачи «Фалькон Тех», ЛЦТ 2026: по кадру 1920×1080 и рамке автомобиля найти ту же машину среди кадров
с других камер и выдать десять кандидатов — либо отказаться от ответа, если машины в галерее нет.

В `main` лежит только то, что участвует в сдаче: код инференса и обучения финальной модели, их конфиги, протокол
валидации и сборка образа. Все 208 экспериментов, их карточки и реестр — в ветке
[`experiments`](../../tree/experiments).

## Что сдаётся

Одна модель, один прямой проход на автомобиль:

```
кадр 1920×1080 + рамка
  → вырезка по рамке, длинная сторона ≤ 512 px
  → сжатие до 224×224, нормализация SigLIP
  → SigLIP 2 So400m/14 (27 блоков, ширина 1152, 16×16 = 256 патч-токенов), fp16
  → attention pooling → BNNeck → L2 → эмбеддинг 1152        ─┐
  → среднее патч-токенов → Linear 1152×3 → ракурс           ─┤
                                                             ▼
  поиск: cos(q, g) − 0,07 · [ракурс совпал] → top-10 → submission.csv
  отказ: z-оценка топ-1 (без штрафа) ≥ 7,0828 → строка в candidates.csv
```

- **Башня** — публичные веса `ViT-SO400M-14-SigLIP2` (webli), дообученные в два этапа: претрейн на VERI-Wild test,
  затем все пять фолдов обучающей выборки с ArcFace (imprinting центров) + SupCon + batch-hard triplet.
- **Суп** — равновесное усреднение весов трёх сидов: одна модель, без роста времени и размера.
- **Поправка на ракурс** — штраф кандидату, снятому с той же стороны, что запрос: 77% потерянного AP приходится
  на смену ракурса, а неверный первый ответ совпадает с запросом по ракурсу в 80% случаев против 37% у случайного
  кадра. Голова ракурса — матрица 1152×3 на токене, который и так посчитан; второй сети не нужно.
- **Отказ** — по z-оценке лучшего кандидата относительно распределения сходств этого запроса; порог получен
  калибровкой leave-one-fold-out на пяти фолдах.

Ни номеров, ни `camera_id`, ни query expansion, ни кластеризации по запросам — потоковый протокол соблюдён.

## Как запустить

Нужны Docker с Compose и NVIDIA Container Toolkit. Каталог датасета (`images/`, `test_query.csv`,
`test_gallery.csv`) монтируется в `/data` только для чтения, результат появляется в `submission/`:

```bash
DATASET_DIR=/путь/к/датасету docker compose up --build
```

Сборка скачивает веса по адресу, закреплённому на ревизии, и проверяет sha256 (`configs/weights.json`); запуск
контейнера идёт без сети, `HF_HUB_OFFLINE=1`. Контейнер получает все GPU хоста и работает от root, чтобы писать
в `submission/` независимо от владельца каталога.

Без Docker:

```bash
pip install -r requirements-inference.txt
PYTHONPATH=src python -m reid.submit --data-config configs/data.yaml --config configs/final_model.yaml
```

На выходе три файла в формате организаторов: `submission.csv` (10 кандидатов на запрос, без заголовка),
`candidates.csv` (одна строка на отвеченный запрос) и `embeddings.npy` (float32, сначала все query, затем gallery).
Проверены их собственными загрузчиками из `evaluate.py`.

## Обучение с нуля

Код обучения в `main` — урезанная копия ветки `experiments` (коммит `c47c34d`): те же функции и те же пути
исполнения, без веток отклонённых экспериментов. На CPU сверено побитово с исходным кодом: состав и порядок
батчей PK-сэмплера, аугментации на реальных вырезках, лоссы, imprinting ArcFace, оценка фолда, суп, функции порога.
Обучение на GPU недетерминировано, поэтому повторённые веса совпадут с опубликованными с точностью до этого шума;
инференс детерминирован.

Окружение обучения: Python 3.13.7, NVIDIA H200, bf16.

```bash
pip install -r requirements-train.txt --index-url https://download.pytorch.org/whl/cu130
pip install -r requirements.txt
```

Пути задаёт `configs/data.yaml`. Все команды — из корня репозитория с `PYTHONPATH=src`; `D=configs/data.yaml`.

Пояснения к шагам:

- **Протокол валидации** закоммичен в `protocol/val_v2/`: фолды по машинам и для каждого фолда псевдотест как на
  тесте (галерея — один кадр на пару «машина, камера», запросы — остальные кадры; ~20% запросов без пары). Он
  воспроизводится из `train.csv` командами `python -m reid.protocol` с `configs/train/val_v1.yaml`, затем
  `configs/train/val_v2.yaml` — побитово те же 16 файлов. `camera_id` используется только здесь и в PK-сэмплере,
  как разрешили организаторы; на вход модели он не подаётся.
- **Метки ракурса** для шага 4 закоммичены в `protocol/attributes.csv`: zero-shot CLIP ViT-B/16 на кадрах
  `train.csv`, `python -m reid.attributes --data-config $D --config configs/train/clip_labeller.yaml`. Тестовые
  кадры не размечаются: на тесте ракурс даёт голова, а не CLIP.
- **Порог**: сдаваемая модель обучена на всех фолдах, поэтому свой порог ей подобрать не на чем. Рецепт обучается
  ещё пять раз, каждый раз без одного фолда; порог каждого прогона — центр плато, где 0,7·F1 + 0,3·TNR (как
  в `evaluate.py`) держится в пределах 0,001 от максимума на невиданном фолде. Центры: 7,0363 / 6,8675 / 7,0805 /
  7,0528 / 7,0915, медиана 7,0528; плюс 0,03 — сдвиг z-оценки топ-1 при переходе от одного сида к супу трёх сидов
  (EXP-161 → EXP-164: 7,251 → 7,280). Итог 7,0828. Балл отказа держится в пределах 0,005 от максимума на полосе
  шириной 0,567, что больше разброса центров (0,224): даже прежний порог 7,2429 стоил бы в среднем 0,005 балла
  отказа (EXP-202).
- **Две константы не подбираются заново в `main`**: штраф ракурса 0,07 выбран на фолде 0 в EXP-190 и подтверждён
  на всех пяти фолдах моделями, не видевшими фолд (EXP-204: +0,0031 mAP@10 в среднем, прирост на каждом фолде),
  и сдвиг 0,03 выше. Оба измерения с кодом — в ветке `experiments`.

## Что было только экспериментом и в сдаваемое решение не входит

В ходе исследования в ветке `experiments` проверялись и отклонялись разные идеи. Часть из них при чтении истории
может вызвать вопросы, поэтому перечисляем их явно.

- **Псевдоразметка тестовых кадров (EXP-162/163) — только эксперимент, финальное решение её не содержит.**
  В EXP-162 кадры публичных `test_query.csv` и `test_gallery.csv` (без каких-либо меток) были сгруппированы
  ансамблем моделей в 282 псевдомашины, в EXP-163 их добавили к обучению. Прироста это не дало (−0,004 mAP@10,
  доверительный интервал включает ноль; сумма баллов −0,13), и приём был отклонён. Сдаваемая модель получена
  цепочкой EXP-040 → EXP-205 → EXP-206 (+ голова EXP-208, порог EXP-202) и обучалась только на VERI-Wild test
  и `train.csv`; в `reid.train` ветки `main` нет даже кода загрузки псевдометок. Тестовые кадры в сдаваемом
  пайплайне используются только на инференсе, каждый запрос — независимо. Конфиги и таблица этого эксперимента
  остаются в ветке `experiments` (`configs/exp162_*`, `configs/exp163_*`, `protocol/pseudo/`) для прозрачности.
- **Camera-adversarial голова (EXP-157)**, где `camera_id` был целью вспомогательного лосса, — отклонена
  (−0,006 mAP@10). В финальном обучении `camera_id` используется только в PK-сэмплере и в протоколе валидации.
- **Query expansion (αQE, EXP-104/105/165) и попарный переранжировщик (EXP-168–170)** — в сдачу не вошли. αQE
  исключён в EXP-178: при честном пороге не помогает, делает порог неустойчивым, а query expansion организаторы
  запретили. Переранжировщик ничего не добавил поверх поправки на ракурс (EXP-191).
- **Диагностики на тестовых кадрах без меток.** При приёмке финальной модели сверялась доля совпадающих верхних
  ответов двух моделей одного рецепта (EXP-205); в EXP-207 сравнивалось распределение z-оценок тестовых запросов
  с фолдом 4, чтобы понять, почему на тесте мало отказов. Правило выбора в EXP-207 было записано до запуска и от
  теста не зависело; ни один параметр сдаваемой модели по тестовым кадрам не подбирался. Для анализа ошибок по
  срезам в ветке `experiments` CLIP проставил ракурс, цвет и признак такси и тестовым кадрам; в `main` эти метки
  есть только у обучающих кадров, и голова ракурса обучена только на них.

## Исследование

Ветка [`experiments`](../../tree/experiments) — 208 экспериментов с карточками и реестром
(`experiments/registry_val_v2.csv`). Правила: одно изменение за эксперимент, три сида на точку, решение по парному
bootstrap по машинам, отложенный фолд открывается только по заранее записанному правилу. Самое полезное там —
список того, что **не** сработало: маски SAM, подмена фона, цветовые и ночные аугментации, AFEM, OSNet,
sub-centre ArcFace, псевдоразметка, дистилляция, 60 эпох.

## Ограничения

- Модель обучена на всех пяти фолдах, поэтому её собственного замера нет — есть замер предыдущей конфигурации
  на нетронутом фолде 4 и кривая обучения.
- Порог отказа откалиброван на пяти фолдах вне выборки; на публичном тесте он отказывает в 5,5% запросов.
  Если в закрытом тесте «запрос без пары» устроен иначе (машина остаётся в галерее, но только с камеры запроса),
  z-оценка к таким запросам слепа — измерено, записано в карточке EXP-207 ветки `experiments`.
