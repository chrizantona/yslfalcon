# Falcon · поиск автомобилей без номеров

**YSL MISIS · НИТУ МИСИС · БИВТ-24-9**

Сервис повторной идентификации автомобилей по фотографии. Находит одну и ту же машину на кадрах разных камер по её внешнему виду — даже если номер отсутствует, закрыт или не читается.

Проект разработан для задачи № 7 компании «Фалькон Тех» на хакатоне «Лидеры цифровой трансформации — 2026». В репозитории собраны обученная ReID-модель, код исследования и веб-приложение для оператора.

Команда YSL MISIS заняла **2-е место** в задаче «Фалькон Тех» на ЛЦТ 2026.

## Установка и запуск

### Требования

- Git, Docker и Docker Compose v2.
- Python 3.12+ для скриптов запуска сервиса.
- Свободный порт `8090`.
- Для поиска с обученной моделью — NVIDIA GPU и NVIDIA Container Toolkit.

```bash
git clone https://github.com/chrizantona/yslfalcon.git
cd yslfalcon/service
```

### С обученной моделью

```bash
./scripts/start_model.sh
```

Скрипт собирает приложение, скачивает веса с проверкой SHA-256 и запускает пять контейнеров. Первая сборка требует загрузки около 8 ГБ зависимостей и весов. После сборки сервис работает без внешнего интернета.

### Знакомство с интерфейсом без GPU

```bash
./scripts/start.sh
```

В этом режиме используется явно обозначенная заглушка: можно пройти весь сценарий работы с галереями, поиском и отчётами. Результаты заглушки не подтверждают совпадение автомобилей.

| Сервис | Адрес |
|---|---|
| Веб-интерфейс | [localhost:8090](http://localhost:8090) |
| Документация API | [localhost:8090/docs](http://localhost:8090/docs) |

Параметры окружения, запуск без Docker и проверки описаны в [инструкции сервиса](service/README.md). Подготовка файлов для соревнования запускается отдельно из корня репозитория — см. [технический отчёт](TECHNICAL.md#как-запустить).

## Основной функционал

| Возможность | Как это работает |
|---|---|
| Поиск по фотографии | Оператор загружает кадр, выделяет автомобиль и получает ранжированный список кандидатов. |
| Галереи изображений | Импорт JPEG/PNG и CSV с координатами автомобилей; загрузка частями и проверка файлов. |
| Сравнение кандидатов | Запрос и два кандидата рядом, синхронное масштабирование, координатные пометки и заключение оператора. |
| История и версии | Результат сохраняется вместе с версией галереи; его можно открыть повторно и сравнить изменения между версиями. |
| Экспорт результатов | PDF, JSON, CSV и автономное ZIP-дело с изображениями, просмотрщиком и проверкой целостности. |
| HTTP API | Импорт, поиск, работа с результатами и отчётами доступны через документированный API. |

Модель формирует визуальный признак автомобиля и сравнивает его с признаками галереи. Для ускорения поиска сервис использует индекс FAISS HNSW с последующим точным пересчётом сходства кандидатов.

При недостаточной уверенности система может отказаться от ответа. В сервисе калиброванный отказ доступен для галерей от 500 до 1 000 кадров; для других размеров интерфейс сообщает, что калибровка недоступна.

## Технологии и инструменты

| Часть проекта | Технологии |
|---|---|
| Интерфейс | React 19, TypeScript, Vite |
| API и фоновые задания | Python, FastAPI, SQLAlchemy |
| Хранение и поиск | PostgreSQL, FAISS HNSW |
| Компьютерное зрение | PyTorch, SigLIP 2 So400m/14, OpenCLIP, CUDA |
| Отчёты | ReportLab, PDF / JSON / CSV |
| Инфраструктура | Docker, Docker Compose, nginx |

Модель обрабатывает вырезку `224 × 224` и выдаёт эмбеддинг размерности `1152`. Отдельная голова определяет ракурс; при ранжировании учитывается поправка на совпадение ракурсов. Веса, конфигурация и код модели общие для сервиса и решения соревнования.

## Архитектура и структура проекта

Сервис состоит из пяти контейнеров. API принимает запросы, worker выполняет фоновые задания, а отдельный runtime вычисляет признаки автомобилей. PostgreSQL хранит метаданные, эмбеддинги, версии галерей и историю поиска.

```text
Оператор → Web (React / nginx) → API (FastAPI) → PostgreSQL
                                    ↓              ↑
                                  Worker ──────────┘
                                    ↓
                              Runtime (SigLIP 2)
```

Модель вынесена в отдельный процесс: интерфейс, API и обработка заданий используют один HTTP-контракт как с обученным энкодером, так и с заглушкой для демонстрации.

```text
yslfalcon/
├── src/reid/             # Обучение, инференс и подготовка файлов сдачи
├── configs/              # Конфигурации модели, обучения и манифест весов
├── protocol/             # Фолды валидации и метки обучающих данных
├── tests/                # Проверки модельного кода
├── service/
│   ├── backend/          # API, worker, runtime и векторный поиск
│   ├── frontend/         # Интерфейс оператора
│   ├── runtime/          # Сборка и проверка весов обученной модели
│   ├── scripts/          # Запуск, сборка и проверки сервиса
│   └── docs/             # Архитектура и документация
├── Dockerfile            # Образ решения соревнования
├── docker-compose.yml    # Запуск подготовки файлов сдачи
└── TECHNICAL.md          # Модель, обучение, эксперименты и валидация
```

## Результаты

| Показатель | Значение | Условия измерения |
|---|---:|---|
| Качество поиска, mAP@10 | **0,9000** | Отложенный фолд 4, 1 112 запросов; обучение на фолдах 0–3 |
| Обработка одного автомобиля | **25,61 мс** | RTX A5000, полный цикл от чтения файла до эмбеддинга |
| Производительность | **212,2 FPS** | RTX A5000, размер батча 32 |
| Суммарный размер весов | **≈ 1,72 ГБ** | Энкодер и голова ракурса |

Качество измерено на отложенной выборке. Финальная модель дообучена на всех пяти фолдах; отдельного замера её качества на закрытом тесте в репозитории нет. Замеры скорости относятся к модельному пайплайну, без веб-интерфейса и HTTP API.

Исследование включает 208 экспериментов: сравнение моделей, функций потерь, аугментаций, способов обучения и ранжирования. Методика валидации, калибровка отказа, ограничения и источники данных сохранены в [техническом отчёте](TECHNICAL.md), карточки экспериментов — в ветке [`experiments`](https://github.com/chrizantona/yslfalcon/tree/experiments).

## Демонстрация работы

Чтобы познакомиться с приложением:

1. Запустите сервис и откройте [localhost:8090](http://localhost:8090).
2. Создайте галерею, загрузите изображения и CSV с рамками автомобилей.
3. Дождитесь обработки и активируйте подготовленную версию галереи.
4. Загрузите кадр запроса, выделите автомобиль и откройте кандидатов для сравнения.
5. Сохраните заключение и скачайте отчёт или автономное дело.

[Презентация проекта на Google Drive](https://drive.google.com/file/d/17oiK0vA40fQt4GNCYmYNw45ZSNDoW9Sl/view?usp=sharing) — постановка задачи, команда, архитектура модели, исследование и направления развития.

Подробности интерфейса — в [описании возможностей сервиса](service/docs/JURY_FEATURES.md), схема компонентов — в [документе об архитектуре](service/docs/ARCHITECTURE.md).

## Практическая ценность и развитие

Falcon помогает искать повторные появления автомобиля в архиве камер, когда распознавание номера недоступно. Оператор получает кандидатов, может сравнить детали и сохранить основания своего решения вместе с исходными изображениями.

В проекте выполнен полный цикл разработки: исследование ReID-модели, обучение и валидация, реализация API и интерфейса, хранение данных, векторный поиск и сборка приложения в Docker.

Следующие направления, предложенные в презентации:

- Поиск автомобиля по текстовому описанию через текстовый энкодер в общем пространстве признаков.
- Использование заключений оператора для подготовки обучающих пар и сложных отрицательных примеров.
- Дообучение модели и уточнение порога отказа на накопленной разметке.

Эти направления относятся к дальнейшему развитию. Текущая версия уже сохраняет пометки и заключения оператора, но не использует их для автоматического дообучения.
