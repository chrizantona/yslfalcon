# yslfalcon

Сервис повторной идентификации автомобилей без номеров — задача «Фалькон Тех», ЛЦТ 2026: по снимку машины и её рамке найти ту же машину на других камерах или отказаться от ответа.

- Правила работы и эксперименты — [`AGENTS.md`](AGENTS.md)
- Данные, ответы организаторов, протокол — [`eda/KEY_FINDINGS.md`](eda/KEY_FINDINGS.md)
- Реестр текущего протокола — [`experiments/registry_val_v2.csv`](experiments/registry_val_v2.csv), карточки — `experiments/EXP-NNN.md`
- Переход на протокол `val_v2` и пересчёт — [`experiments/VAL_V2.md`](experiments/VAL_V2.md)
- Источники данных и весов с sha256, как повторить с нуля — [`DATA.md`](DATA.md)

## Текущее состояние
- **Бейзлайн:** EXP-016 — CLIP ViT-B/16 (LAION-2B) → претрейн на тестовой части VERI-Wild → дообучение на наших фолдах 1–3 → суп весов трёх сидов. mAP@10 = 0,773, баллы отказа 0,872.
- **Скорость EXP-016** (методика организаторов, H200): 14,3 мс на одно ТС, лучший FPS 371 (батч 32), пиковый VRAM 632 МБ, эмбеддинги детерминированы, веса 345 МБ. Порог полного балла — 40 мс и 100 FPS на RTX A5000.
- **Риск в режиме отказа:** если организаторы считают неверным верхнего кандидата, который оказался кадром той же машины с той же камеры, F1 падает до 0,02–0,04 (`F1_strict`). Проверим по их `evaluate.py`.

## Ночной запуск ViT-L
На поде папки `exp1`…`exp5` соответствуют EXP-020…024. `scripts/pod_night_job.sh` сначала запускает обучение ViT-L на GPU 1 и независимый fp16-бенчмарк на GPU 3. После бенчмарка три сида распределяются по отдельным GPU 1/3/2. GPU 2 используется только после проверки свободной памяти и простоя; GPU 0 остаётся сервисам. Если прирост среднего mAP@10 над EXP-003 превышает разброс обоих экспериментов, автоматически следуют претрейн VERI-Wild, три дообучения и суп. Условие в `configs/exp1.yaml`, результат в `exp1/status/gate.json`, общий статус в `exp1/status/night_stage`, завершение — `night_DONE` или `night_FAILED`. Задачи отвязаны от SSH.

Первый замер скорости на публичных весах предварительный; после обучения повторяется на seed0 вместе с BNNeck. Весовой файл хранится в fp32, fp16 применяется к вычислениям. Сравнение качества использует неизменённый `evaluate_fold` и `val_v2`. Фолд 4 не используется.
