# EDA: ключевые выводы и правила разработки

Источник всех цифр — `eda/eda.ipynb` (исходник `eda/eda.py`). Прежде чем менять загрузку данных, валидацию, обучение или сабмит, сверься с этим файлом.

## 1. Задача
- Open-set ReID автомобилей: для каждого снимка из `test_query.csv` упорядочить снимки из `test_gallery.csv` по убыванию сходства и сдать top-10.
- Метрика качества — mAP по всем запросам (45% оценки). **Совпадения с той же камеры исключаются**, засчитываются только кросс-камерные. Rank-1 и Rank-5 — дополнительные столбцы.
- Режим отказа (10%): вернуть кандидатов с уверенностью или пустой ответ. Оценка — F1 и TNR при выбранном нами пороге, порог надо обосновать.
- Производительность (20%): время на одно ТС при батче 1, FPS при пакетной обработке, веса ≤ 2 ГБ, без OOM. Инференс офлайн, в Docker, запуск одной командой.
- Детекция, распознавание номеров и трекинг не нужны: рамки даны.

### Формат сдачи (README датасета)
- `submission.csv`: `query_id, gallery_id_1, …, gallery_id_10`.
- `embeddings.npy`: сначала все `image_id` из `test_query.csv` в порядке файла, затем все из `test_gallery.csv`.
- `candidates.csv`: `query_id, gallery_id, confidence`; при отказе у запроса нет кандидатов.

## 3. Как собран тест (раздел 7 ноутбука)
- **gallery = один случайный кадр на каждую пару «машина + камера»; query = все остальные кадры.** Псевдо-тест, собранный так из train, совпадает с реальным тестом по всем проверкам: отношение query/gallery 1,44–1,49 против 1,48, доля запросов с почти той же рамкой в gallery 75–76% против 74%, соседние строки gallery никогда не из одной серии.
- Следствия:
  - почти у каждого запроса в gallery есть кадр из той же серии (та же камера): модель ставит его первым, но метрика его выбрасывает;
  - засчитываются только кадры той же машины с других камер, у 2/3 машин такой кадр ровно один;
  - в публичном тесте у каждого запроса есть совпадение, поэтому TNR на нём не измерить.
- **CSV теста отсортированы по машинам:** у 84% запросов ближайший снимок gallery лежит в пределах ±10 строк от строки i × 750/1110. Это утечка, её не используем.

## 4. Как делать

### Валидация
1. Делить train **только по `vehicle_id`** (GroupKFold, ~300 машин в фолде). Деление по снимкам запрещено: кадры одной серии утекают между фолдами.
2. В отложенной части собирать псевдо-тест функцией `make_pseudo_test` (раздел 7 ниже) и **перемешивать строки** перед инференсом.
3. Считать mAP, R1, R5 и mINP функцией `reid_eval`: пары «та же машина + та же камера» выбрасываются, остальные кадры той же камеры остаются негативами. Когда организаторы выдадут эталонный скрипт метрики, перейти на него и сверить с `reid_eval`.
4. Порог отказа калибровать на псевдо-тесте с искусственными отказными запросами: убрать из gallery кадры случайных 30% машин. Выбирать порог по максимуму F1 при ограничении снизу на TNR и перенастраивать после каждой смены модели.
5. Уверенность для отказа — **нормированный score**: z-score top-1 относительно всех сходств запроса, отрыв top-1 от top-2 или расстояние после k-reciprocal re-ranking. Сырой косинус не годится: у готовых моделей он не отличает верный ответ от неверного (PR-AUC 0,029 при базовой доле 0,026, у z-score — 0,17).

### Модель
6. Готовые эмбеддинги не годятся (таблица в разделе 6), нужна дообученная ReID-модель: ID-loss плюс triplet или circle loss, PK-сэмплер с позитивами с других камер.
7. Начинать с CLIP-подобных или сильных supervised-бэкбонов. Сырой DINOv2 CLS кодирует ракурс и фон, а не машину.
8. Кадры одной серии считать одним видом при сэмплировании: остальные кадры почти копии.
9. Снизить вес пары камер 89/90 в сэмплере и отдельно проверять метрику на ней.
10. Бороться со смещением по камере: негативы с той же камеры, camera-wise BN или вычитание среднего эмбеддинга камеры (даже без обучения даёт +22–32% mAP).
11. Ракурс — главный источник ошибок: flip, crop, random erasing; сравнить вход 320×240 (под w/h ≈ 1,35) с 256×256; part- или attention-головы; k-reciprocal re-ranking.
12. Ночь и низкое качество закрывать аугментациями яркости и цвета, отдельная ветка не нужна.
13. Следить за временем на батче 1 и суммарным размером весов (≤ 2 ГБ): это 20% оценки.

## 5. Запрещено
- Использовать номерные знаки и любые их остатки: дисквалификация.
- Использовать порядок строк, соседство строк, `image_id` или md5 файлов как признак, фильтр или тай-брейк.
- Эксплуатировать продублированные кадры.
- Использовать `camera_id` на инференсе: в тесте его нет. Id камер, выведенные по фону (точность 93%), — только после явного разрешения организаторов.
- Оценивать модель без исключения совпадений с той же камеры: серии завышают метрику.

Самые трудные запросы:
- машина не видна в том же ракурсе на другой камере (mAP 0,02 против 0,07);

- чёрные, серые и зелёные машины.

Главные ложные совпадения — однотипные машины каршеринга и такси, а также чужие машины с той же камеры в том же ракурсе.

## 7. Код протокола (из ноутбука)

```python
import numpy as np


def make_pseudo_test(df, seed=0, n_vehicles=None):
    """Test recipe: gallery = one random frame per (vehicle, camera), query = the rest.
    df: train rows with vehicle_id and camera_id. Indices come back sorted -> shuffle before inference."""
    if n_vehicles:
        keep = np.random.default_rng(seed).choice(df.vehicle_id.unique(), n_vehicles, replace=False)
        df = df[df.vehicle_id.isin(keep)]
    gal = df.groupby(["vehicle_id", "camera_id"]).sample(1, random_state=seed).index
    return np.sort(df.index.difference(gal).to_numpy()), np.sort(gal.to_numpy())


def reid_eval(sim, q_pid, q_cam, g_pid, g_cam, chunk=1024, topk_junk=10):
    """Market-1501 protocol: gallery items with the same vehicle AND camera as the query are junk (ignored).
    sim: (n_query, n_gallery) similarity matrix; *_pid = vehicle ids, *_cam = camera ids."""
    ap, r1, r5, inp, junk10 = [], [], [], [], []
    for s in range(0, len(q_pid), chunk):
        S = sim[s: s + chunk]
        order = np.argsort(-S, axis=1)
        match = g_pid[order] == q_pid[s: s + chunk, None]
        junk = match & (g_cam[order] == q_cam[s: s + chunk, None])
        good, valid = match & ~junk, ~junk
        cv_, cg = np.cumsum(valid, 1), np.cumsum(good, 1)
        npos = good.sum(1)
        rows = np.arange(len(S))
        first = cv_[rows, good.argmax(1)]
        last = cv_[rows, good.shape[1] - 1 - good[:, ::-1].argmax(1)]
        ok = npos > 0
        ap.append((np.where(good, cg / np.maximum(cv_, 1), 0).sum(1) / np.maximum(npos, 1))[ok])
        r1.append(first[ok] <= 1)
        r5.append(first[ok] <= 5)
        inp.append((npos / last)[ok])
        junk10.append(junk[:, :topk_junk].sum(1)[ok])
    ap, r1, r5, inp, junk10 = map(np.concatenate, (ap, r1, r5, inp, junk10))
    return {"mAP": ap.mean(), "R1": r1.mean(), "R5": r5.mean(), "mINP": inp.mean(), "junk in top-10": junk10.mean()}, ap
```
